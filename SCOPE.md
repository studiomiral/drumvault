# Warehouse — Project Scope

> A personal macOS desktop app that builds club house tracks from your own material. Its core, the **Drumvault**, turns zips of dance-track stems into a tempo-matched, key-labeled **drum** sample library; around it, Generate writes whole tracks (drums, FX, bass, chord stabs, strings, disco hits), a minimal timeline DAW arranges them, and stems export for finishing in Logic Pro. (The app was called Drumvault until its scope grew; the repo, the engine package, the library folder and the project file format keep that name.)

**Owner / only user:** Lars (personal use — no distribution, no licensing concerns, no code signing required).
**Target machine:** MacBook Pro M1 Pro (Apple Silicon), 32 GB RAM, macOS Tahoe.
**Downstream DAW:** Logic Pro.

---

## 1. Goals

1. Drag one or many `.zip` files of stems into the app.
2. Automatically keep only **drum stems**, analyse them, and write finished samples into **one target library folder**:
   - **One-shots** (unstretched) from single-sound stems: kick, snare, clap, hats, rides, perc, etc.
   - **Loops**, time-stretched to a single library BPM: hats, perc, shakers, tops, grooves, full drum loops.
   - **FX & fills** ("events"), time-stretched like loops and cut on the bar grid: drum fills, snare rolls, risers, downlifters, impacts, sweeps. (Atmos stems are cut the same way but filed on the Ambience page, §6.10a, not in the drum library.)
3. **BPM** is detected on the zip's **kick stem** and applied to every stem in that zip.
4. Every sample is labeled with the **source track key**, detected from the zip's melodic stems (which are then discarded).
5. Normalize, deduplicate, name, and index all samples in a searchable library.
6. A **mini DAW**: lanes on a bar grid, drag samples from the library, arrange a full track structure, play it back, and **export one full-length WAV per lane**, all starting at bar 1, ready to drop into Logic.

## 2. Non-goals (explicitly out of scope)

- Melodic samples (bass, synths, vocals). Melodic stems are only used for key detection, never exported. Vocals (including "Vocal FX") are ignored.
- Effects, automation, MIDI, recording, plugins (VST/AU) in the DAW. Two exceptions (Phase 5): a per-clip low-pass/high-pass filter, fixed or swept over the clip, for filtered kicks and filter builds; a per-clip reverb send rising over the clip, for reverb builds (§6.6); and a per-lane EQ (a low cut and a few broad bands) for the generated mix, baked into the stems (§6.6).
- Real-time time-stretching or pitch-shifting in the DAW. The DAW plays samples at native speed at the library BPM (exceptions: 16th slicing for other tempos, §6.4a, and sampler-style pitch on drum clips, §6.4 — both just a playback rate per slice, no DSP).
- Windows/Linux support, auto-updates, code signing, notarization, multi-user anything.
- Stem separation (Demucs etc.) — inputs are already separate stems.

## 3. Tech stack

| Layer | Choice | Why |
|---|---|---|
| Desktop shell | **Electron** + TypeScript | Chromium Web Audio is consistent and reliable; familiar JS/TS world |
| UI | **React + Vite** + TypeScript, Tailwind CSS | Lightweight; Next.js is unnecessary inside Electron |
| State | Zustand (+ immer) | Simple, works well for timeline state + undo/redo |
| Audio playback (DAW) | Web Audio API in the renderer | Sample-accurate scheduling, OfflineAudioContext for export |
| Analysis/processing engine | **Python 3.12 sidecar**, managed with **uv** | Best audio tooling |
| Python libs | numpy, scipy, soundfile, librosa, essentia (key), pyloudnorm (optional) | |
| Time-stretch | **Rubber Band** CLI (macOS: `brew install rubberband`; Linux cloud: `apt-get install rubberband-cli`), called via subprocess | Best quality available; GPL is fine for personal use |
| Library index | **SQLite** (WAL mode); Python writes, Electron reads via Node's built-in `node:sqlite` (read-only) | No native module to rebuild for Electron (originally planned: better-sqlite3) |
| Engine ↔ app | JSON-lines RPC over the sidecar's stdin/stdout | No ports, no servers |

Startup check: the app verifies `rubberband` and the Python environment exist and shows a clear setup message if not.

If `essentia` won't install cleanly on Apple Silicon, use the fallback key detector described in §5.5 (chroma + EDM key profiles in numpy). Keep key detection behind one interface so either backend can be used.

## 5. Processing engine (Python)

### 5.1 Pipeline per zip

```
zip → extract to temp dir → discover audio files → classify stems
    → detect BPM + grid (kick stem) → detect key (melodic stems)
    → one-shots from ORIGINAL (unstretched) single-sound stems
    → stretch drum + event stems to library BPM → slice loops / cut events on the grid
    → filter silence → dedupe → normalize → write files → peaks → index in DB
    → clean temp dir
```

Jobs are processed one zip at a time (queue). Within a zip, per-stem work may use a process pool. Each stage emits progress events.

A zip is identified by a **SHA-1 of the zip file**. Re-dropping an already processed zip is skipped unless the user chooses "Reprocess".

### 5.2 Extraction & discovery (`zipio.py`)

- Support nested folders and nested zips (one level deep).
- Ignore `__MACOSX/`, `._*`, `.DS_Store`, and hidden files.
- Accept `.wav`, `.aif`, `.aiff`, `.flac`. Skip `.mp3`/others with a warning in the job log.
- Load as float32; keep native sample rate during analysis. Stereo is preserved for output; analysis uses a mono downmix.
- Warn (not fail) if stem lengths differ by more than 1 bar's worth of samples — this suggests they weren't exported from bar 1.

### 5.3 Stem classification (`classify.py`)

**Step 1 — filename rules** (case-insensitive, word-boundary-aware, checked in this priority order so "Bass Drum" isn't caught as bass, "Snare Roll" is a roll and "Vocal FX" stays ignored):

| Category | Keywords |
|---|---|
| `ignore` (vocals, checked first) | vox, vocal, vocals, voice, acapella |
| `roll` | roll, snare roll, drumroll, snare build (whole word: "Rolling Bass" is not a roll) |
| `fill` | fill, drum fill (whole word) |
| `fx_riser` | riser, rise, uplifter, upsweep, build up |
| `fx_downlifter` | downlifter, downsweep |
| `fx_impact` | impact, sub drop, boom, explosion |
| `fx_sweep` | sweep, whoosh, noise, white noise, reverse (so "Reverse Crash" is FX, not a cymbal) |
| `fx_atmos` | atmos, atmosphere, ambience, texture (its cuts go to the Ambience page, §6.10a) |
| `fx` | fx, sfx, effect, effects |
| `kick` | kick, kik, bd, bassdrum, bass drum |
| `clap` | clap, cp, handclap |
| `snare` | snare, sd, rim, rimshot |
| `hat_closed` | closed hat, ch, chh, hihat closed |
| `hat_open` | open hat, oh, ohh |
| `hat` | hat, hats, hh, hihat, hi-hat |
| `ride` | ride |
| `cymbal` | crash, cymbal, china, splash |
| `shaker` | shaker, shake, tamb, tambourine, maracas |
| `perc` | perc, percussion, conga, bongo, tom, cowbell, clave, wood, block, timbale |
| `top` | top, tops, top loop |
| `groove` | groove, grooves |
| `drums` | drums, drum, drum bus, drumbus, beat, loop (only if no melodic keyword) |
| `melodic` (key only) | bass, sub, synth, lead, pad, chord, chords, keys, piano, stab, pluck, arp, organ, string, music, melody |
| `full_mix` (key fallback) | master, mix, full, mixdown |
| `ignore` | reverb return, send |

**Step 2 — audio fallback** for files that match no rule: compute harmonic/percussive energy ratio (librosa HPSS), spectral flatness, and onset density. Clearly percussive → `drums` (or a more specific category if the spectral centroid strongly suggests kick or hats); clearly harmonic → `melodic`; otherwise `ignore`. Mark these stems `auto_classified = true` so the UI can highlight them for review.

The user can override any stem's category in the UI and reprocess the zip.

### 5.4 Tempo & grid (`tempo.py`)

Source: the zip's `kick` stem. Fallback order if missing: `drums` → `clap`/`snare` → `full_mix` → sum of all stems. Fallbacks reduce the confidence score.

Algorithm:
1. Mono, low-pass ~150 Hz, onset envelope (librosa), pick strong onsets with backtracking for precise attack times.
2. Rough BPM from the onset envelope via autocorrelation, constrained to the configured range (default **115–135 BPM**) to avoid half/double errors.
3. **Refine** by fitting a linear grid `t_n = phase + n · period` to the onset times (nearest-beat assignment + least squares, iterate 2–3×).
4. Source tracks are always whole-number BPM: round the refined BPM to the nearest integer. If it was more than ±0.05 away from that integer, flag `needs_review` (the detection is suspect) unless a filename BPM confirms it. (Configurable: `integer_bpm`.)
5. If the zip name or any stem filename contains a BPM (regex `(\d{2,3}(?:\.\d+)?)\s?bpm`, case-insensitive) within ±1 of the detected value, use the filename BPM.
6. **Grid phase / bar 1**: assume stems were exported from bar 1 (sample 0 = downbeat). Validate: if the fitted phase is within ±15 ms of 0 modulo one beat, use phase = 0. Otherwise check the other drum stems first: if their hits (median) sit within ±15 ms of a 16th grid from sample 0, the export does start at bar 1 and only the kick is late (a slow attack or a nudged sample): keep phase = 0 and note it. Only when the other drums are offset too, use the first strong kick onset as the downbeat and flag `grid_warning`. (A late kick taken as bar 1 cuts every loop late, so they flam against loops from other zips.)
7. **Confidence** = fraction of strong onsets within ±10 ms of the grid. Logged only: it never flags a zip or shows in the UI. The detected BPM is trusted; Lars overrides it when it's wrong.

Output: `{bpm, phase_samples, confidence, source_stem, warnings[]}`.

User override in the UI: BPM and grid offset (in ms or beats) → reprocess.

### 5.5 Source-track key (`key.py`)

- Input: all stems classified `melodic`, summed. If none, use `full_mix`. If neither exists → key = `null` (filename label `NoKey`).
- Weight bass stems ×1.5 in the sum (house keys are most clearly defined by the bassline).
- Primary: essentia `KeyExtractor` with `profileType="edma"` (tuned for electronic dance music).
- Fallback (if essentia unavailable): librosa CQT chroma, averaged over non-silent frames, matched against EDM-style major/minor key profiles (correlation over all 24 rotations).
- Output: `{key: "A", scale: "minor", label: "Am", camelot: "8A", confidence}`. Below 0.5 confidence → still store, but mark `key_uncertain` (UI shows it with a "?" badge).
- User can override the key in the UI.
- The detected key is applied to **every sample** from that zip.

### 5.6 One-shots (`oneshots.py`)

**From the original, unstretched audio** — never time-stretch one-shots.

Source stems: `kick`, `clap`, `snare`, `hat`, `hat_closed`, `hat_open`, `ride`, `cymbal`, `shaker`, `perc`. Not from `top`, `groove`, or `drums` (too many overlapping sounds).

Steps:
1. Onset detection with backtracking.
2. Each candidate hit runs from its onset to the next onset (or end of file).
3. Discard candidates shorter than the minimum length for the category (defaults: kick 200 ms, snare/clap 200 ms, hat_closed 50 ms, hat_open 150 ms, ride 300 ms, cymbal 500 ms, perc/shaker 60 ms).
4. **Trim the tail** at −60 dBFS relative to the hit's peak, or at the next onset if sooner. Apply a 5 ms fade-out; no fade-in (preserve the transient). Cap length at 2 s (cymbals 4 s).
5. Prefer "clean" hits: rank by (a) gap to the next onset, (b) peak level, (c) low pre-onset energy (nothing bleeding in).
6. **Dedupe**: fingerprint each hit (log-mel spectrogram of the first 150 ms, flattened and L2-normalized). Hits with cosine similarity > 0.97 are the same sound; keep the best-ranked one.
7. Within `hat`-category stems, split into `hat_closed` / `hat_open` by decay length (−40 dB decay time > 150 ms → open).
8. Keep at most **N distinct one-shots per stem** (default 4).

### 5.7 Stretching (`stretch.py`)

- Applies to drum stems used for loops only.
- Stretch the **whole stem once**, before slicing, so loop boundaries stay sample-exact and no edge artifacts appear.
- Ratio = `source_bpm / library_bpm`. After stretching, the new phase = `phase_samples / ratio` (rounded).
- Rubber Band CLI, R3 engine (`--fine`), tempo-only (pitch preserved). Verify flags against `rubberband --help` of the installed version and keep options configurable in `config.py`.
- If `|1 − ratio|` > the max stretch setting (default **15%**), skip loops for this zip, still extract one-shots, and flag `needs_review`.
- If ratio == 1.0 exactly, skip stretching.
- Resample to the output sample rate (default 44.1 kHz) at this stage if needed.

### 5.8 Loops (`loops.py`)

Source stems and default loop lengths (in bars, configurable):

| Category | Loops? | Default lengths |
|---|---|---|
| kick | no (one-shots only) | — |
| snare, clap | yes | 2, 4 |
| hat, hat_closed, hat_open, ride, shaker, perc | yes | 1, 2, 4 |
| top, groove, drums | yes | 2, 4, 8 |
| cymbal | no | — |

Steps:
1. Bar length in samples = `round(sr · 60 / library_bpm · 4)`. Slice positions = `phase + k · bar_len · length` for k = 0, 1, 2, …, with **non-overlapping** slices per length.
2. **Silence filter**: drop a slice if RMS < −50 dBFS, or if more than 50% of its beats are silent (per-beat RMS < −55 dBFS). This removes breakdowns where the part drops out.
3. **Dedupe** per stem and length: fingerprint = log-mel spectrogram (coarse time resolution, e.g. 32 frames per bar), L2-normalized. Cosine similarity > 0.96 → duplicate; keep the first occurrence. This is the step that turns 40 copies of the same 4 bars into 1–5 real variations.
4. Optional per-stem cap: max loops per length (default 6), keeping the most mutually distinct ones (greedy farthest-point selection on fingerprints).
5. Loops are cut exactly on the grid with **no fades** (they must loop seamlessly). Only if the first sample is not near zero, apply a 1 ms fade-in to prevent a click; never fade the end.

### 5.8a Events: fills, rolls and FX (`events.py`)

Stems in the categories `fill`, `roll` and `fx_*` / `fx` are mostly silent with a sound every few bars (a fill before the drop, an 8-bar riser, a downlifter after it). Each sound becomes one sample that starts on the bar line where it begins, so it drops onto the timeline exactly where it sat in the source track.

1. The whole stem is stretched to the library BPM first (as for loops, §5.7). If the stretch exceeds the max stretch setting, events are skipped like loops.
2. A beat is *active* if its RMS is within −50 dB of the stem's peak (and above −70 dBFS). Active beats separated by ≤ 2 quieter beats form one region.
3. The event starts on the bar line at or before the region's first sample above that level. A start within **30 ms before a bar line** belongs to that bar (Rubber Band smears ~15 ms of pre-ring ahead of a transient; early flams belong to the bar).
4. The event runs for **whole bars, tail included** (an 8-bar roll that rings into the next bar is a 9-bar sample), so it works as an audio clip on the grid. If a neighbouring event shares its first or last bar, that part is silenced with a 5 ms fade.
5. Regions longer than 32 bars (atmos beds) are cut into 8-bar chunks.
6. Skip events quieter than −30 dB relative to the stem's loudest. **Dedupe**: same fingerprint as loops (per bar), only events of equal length compared, cosine > 0.96 = duplicate, first occurrence kept. Cap: 6 per stem (farthest-point selection).
7. Peak normalize to −1.0 dBFS. Key label, BPM and bar count are stored like loops.
8. **Shape** (`events.shape`, stored as JSON in `samples.shape`): per 16th of the written file, its level. Where the sound starts (`onset`), peaks (`peak`) and ends (`end`: the last 16th within `shape_sound_rel_db` = −24 dB of its loudest, up to the body's end; sound ringing on past it counts as reaching it), and `gap` = 16ths from `end` to the end of the body: the producer's silence before the line it leads into (a riser stopping on beat 7 of 8 has a gap of 4). `dir`: `rise` (peaks late and gets ≥ 6 dB louder or ≥ 0.7 octave brighter from its first to its last beat of sound), `hit` (loudest at once and ≥ 6 dB down a beat later), `fall` (peaks early and gets that much quieter or darker) or `flat`. `noise`: mean spectral flatness (0 a tone, 1 white noise). `boundary`: the bar of the source track (from its bar 1) its body ends on, so events a producer layered at one moment can be found again; null for loose samples (§5.8c). Library "Move sound" measures the shape again.

Events are not one-shots: they are time-stretched, because they must line up with the bar grid at the library BPM.

### 5.8b Grooves and arrangements (`groove.py`, `arrangement.py`)

What the generator needs to sound played rather than programmed (§6.6):
- **Loop groove** (every loop, when it is written): its hits (onsets refined to the attack, the loop treated as cyclic so a hit on sample 0 counts), placed on the 16th grid of the library BPM. Per 16th step of the bar: the median offset in fractions of a 16th (+ late, − early), relative to the loop's own quarter notes when it plays any (else to the grid, which is the source track's kick grid); the median level in dB below the loudest step; and the hit count. Plus `swing` (mean offset of the odd 16ths: +0.33 = MPC 66 %) and `push` (the offbeat 8ths). Stored as JSON in `samples.groove` (`{}` when the loop has too few hits).
- **Track arrangement** (every zip, during analysis, before the melodic stems are let go): each stem measured bar by bar on the track's own grid (its BPM and bar 1) and summed into parts: kick, clap (and snare), hats (and shaker), ride, perc, top (top, groove, drums), crash (cymbal), fills (fill, roll), fx, bass (melodic stems named as bass), music (other melodic). Per part and bar: `0` silent (below `arrangement_silence_db` or 20 dB under the part's full level), `1` quiet or filtered, `2` full (within 6 dB of the part's full level = its 90th-percentile bar). Stored in `arrangements` (one row per zip).
- **Older libraries**: `analyze_library` (a job) fills in grooves from the loop files, event shapes from the event files (the source bar from `source_offset_s` on the zip's stored BPM and bar 1), kept originals (§5.8d) for zips and packs imported before, while they are still where they came from, and arrangements from each zip's stems (on their stored BPM and bar 1). The app starts it by itself when the engine is up and something is missing.

### 5.8c Loose samples (`samples.py`, job `import_samples`)

Zips are whole tracks (tempo, bar 1, key and structure come from all their stems together). Loose samples (Splice and other packs) are already cut, so they don't go through that pipeline: each file is read on its own and lands in the same library.

- **Packs.** Files are grouped by their Splice pack (`…/sounds/packs/<Pack>/…`), else by the dropped folder, else by the file's own folder. A pack is a source like a zip: its own code (`P0001`, separate from `S0001…`), in the Process list with its files as "stems", in the Library's source filter, in Generate's spread over sources. It has no arrangement, so it is never a structure template (§6.6), and no grid (the Grid view leaves packs out). Adding files to a pack's folder later and dropping them adds them to the same pack (the pack is re-cut, favourites and deletions kept); files already in it are skipped.
- **Category:** filename rules (§5.3) on the file name, else on its folders from the nearest up ("Kicks/BBH_03.wav"), else the audio fallback. Overridable per file like stems, then reprocess.
- **Kind:** FX, fills and rolls → event. "One shot"/"hit" in the path (and not "loop" in the file name) → one-shot. Otherwise a **loop** when its length is whole bars: at the BPM in the name ("124bpm", or a bare 60–200 like `BBH_124_Hat_Loop`; a tail after the last whole bar is cut), or without one at the tempo within the max stretch that makes it 1, 2, 4, 8 or 16 bars (closest to the library BPM). Short files (≤ `sample_oneshot_max_s`) that aren't whole bars are one-shots. A "loop" that isn't whole bars, melodic files, longer files and loops too far from the library BPM to stretch are skipped with a warning; only skips a category override or a rename can fix (a loop that isn't whole bars, a one-shot without a single-sound category) flag the pack `needs_review`.
- **Loops** start on their downbeat. Three cycles are stretched to the library BPM (Rubber Band, §5.7) and the middle one kept, so the ends join like a repeat; cut sample-exact to `bars × bar length`, no end fades (§5.8 step 5). Kick and cymbal loops (no loop lengths) give their distinct hits as one-shots instead.
- **One-shots** are never stretched: the best hit of the file (§5.6), or the whole file with its tail trimmed when no onset is found.
- **Events:** stretched when the name has a usable BPM, then cut on bar lines like §5.8a.
- **Key** from the name only ("_Am_", "F#min", "Bb major"; a bare letter is not a key), else none. BPM, normalization, grooves, peaks and file names as for zips (`LP_Hat_124_NoKey_P0001-house-tools_2bar_01.wav`).

### 5.8d Kept originals (`originals.py`)

The library keeps its own copy of what was imported, so the zips and folders dropped in can be deleted afterwards: reprocessing, a new library BPM (`rebuild_loops`), the Grid view's preview and `analyze_library` read the kept copy first and the original only when nothing is kept.

- **Where:** `<Library>/.drumvault/originals/<source code>/`, every audio file of a zip (its path inside the zip, nested zips included) or the pack's files. `kept.json` maps each stem name to its file and is written last; a folder without it (an interrupted copy), or with a file missing, is not used.
- **Lossless:** 8-, 16- and 24-bit PCM (WAV, AIFF) become FLAC at the same bit depth: decoded, the samples are bit-identical, so reprocessing gives the same library. About 60 % of the zip's size. Float and 32-bit files, and files that are FLAC already, are copied as they are. WAV metadata chunks are not kept (nothing reads them).
- **When:** at the end of every import and reprocess of a zip, and for every file a pack gets. Not while the disk would have less than `originals_min_free_gb` free afterwards: the zip then gets a warning to keep the original for now, and `analyze_library` tries again on a later launch (it checks the space before unzipping, and the SHA-1 so a changed zip isn't kept).
- **Delete:** deleting a zip's samples deletes its kept copy too. The zip's `original_path` keeps saying where it came from; the zip panel says "Kept in the library", and Reveal opens the kept folder once the original is gone.

### 5.9 Normalization (`normalize.py`)

- One-shots: peak normalize to **−0.3 dBFS**.
- Loops: peak normalize to **−1.0 dBFS**.
- Optional setting: loudness mode for loops (pyloudnorm, target −14 LUFS short-term, with a peak ceiling of −1 dBFS).
- Store both the original peak and the applied gain in the DB.
- **Loudness** (schema v13): every sample and hit also stores `energy_db`, the K-weighted energy of its mono mix (ITU-R BS.1770 weighting, ungated) in dB, LUFS + 10·log10(seconds): played for T seconds it is `energy_db − 10·log10(T)` LUFS loud. Peak normalisation leaves loudness all over the place (a sparse hat loop and a dense top loop peak alike); Generate's mix balance (§6.6) evens it out. Libraries from before are measured by `analyze_library`.
- **Punch** (schema v15): every sample also stores `punch_db`, the K-weighted level (as LUFS) of its loudest 200 ms (`punch_window_ms`; a shorter sound counts as that long). Against `energy_db` it tells a snappy hit from a washy one of the same energy: all of it within the window, or spread out. Generate's balance uses it for one-shots (§6.6). Libraries from before are measured by `analyze_library` (the app starts it when a sample has none).

### 5.10 Output format, naming & folders (`naming.py`)

- Format: **WAV, 24-bit, 44.1 kHz** by default (settings: 44.1/48 kHz; 24-bit/32-bit float). Stereo stays stereo; mono stays mono.
- Source ID: `S` + 4-digit incrementing zip number (e.g. `S0037`), plus a short slug of the zip name (max 20 chars, ASCII, dashes).

Folder layout in the target library folder:

```
<Library>/
├── One-Shots/
```

Filenames:

### 5.11 Peaks (`peaks.py`)

For every written sample, store min/max peak pairs at ~200 points per second for one-shots, and at a fixed 1024 points per bar for loops, as JSON. The UI never decodes full audio just to draw waveforms.

### 5.12 Database schema (`db.py`)

```sql
CREATE TABLE zips (
  id INTEGER PRIMARY KEY,
  source_code TEXT UNIQUE,          -- "S0037"
  file_name TEXT, file_sha1 TEXT UNIQUE, original_path TEXT,
  detected_bpm REAL, bpm_override REAL, bpm_source_stem TEXT,
  phase_samples INTEGER, grid_offset_override_ms REAL, tempo_confidence REAL,
  key_label TEXT, key_camelot TEXT, key_confidence REAL, key_override TEXT,
  status TEXT,                      -- queued|processing|done|needs_review|error
  reviewed INTEGER DEFAULT 0,       -- "Mark as reviewed": stays done when reprocessed (schema v2)
  warnings TEXT,                    -- JSON array
  processed_at TEXT, settings_hash TEXT,
  kind TEXT DEFAULT 'stems'         -- 'stems' (a zip of one track) | 'pack' (loose samples, schema v8, §5.16)
);

CREATE TABLE stems (
  id INTEGER PRIMARY KEY,
  zip_id INTEGER REFERENCES zips(id) ON DELETE CASCADE,
  file_name TEXT, category TEXT, category_override TEXT,
  auto_classified INTEGER, duration_s REAL, sample_rate INTEGER, channels INTEGER,
  used_for TEXT                     -- JSON: ["tempo","key","oneshots","loops"]
);

CREATE TABLE samples (
  id INTEGER PRIMARY KEY,
  zip_id INTEGER REFERENCES zips(id) ON DELETE CASCADE,
  stem_id INTEGER REFERENCES stems(id) ON DELETE CASCADE,
  kind TEXT,                        -- oneshot|loop|event
  category TEXT,                    -- kick|snare|clap|hat_closed|...|top|groove|drums
  rel_path TEXT UNIQUE,             -- relative to the library root
  bpm REAL,                         -- library BPM for loops, NULL for one-shots
  bars INTEGER,                     -- loops and events (events include their tail)
  body_bars INTEGER,                -- events: bars until the main sound ends (schema v2)
  key_label TEXT, key_camelot TEXT,
  duration_s REAL, sample_rate INTEGER, channels INTEGER,
  peak_db REAL, gain_applied_db REAL,
  source_offset_s REAL,             -- position in the original stem
  fingerprint BLOB,                 -- for dedupe + "similar sounds"
  favorite INTEGER DEFAULT 0, rating INTEGER, tags TEXT,
  shift_beats INTEGER DEFAULT 0,    -- loops/events: Library "Move sound", beats later (schema v5)
  groove TEXT,                      -- loops: timing and accents per 16th, JSON (v7, §5.8b)
  shape TEXT,                       -- events: how it plays and the source bar it leads into, JSON (v9, §5.8a)
  punch_db REAL,                    -- its loudest 200 ms, K-weighted (as LUFS): how hard it hits (v15, §5.9)
  created_at TEXT
);

-- Samples the user deleted (schema v3); reprocessing re-cuts matching ones into the trash.
CREATE TABLE removed_samples (
  id INTEGER PRIMARY KEY,
  zip_id INTEGER REFERENCES zips(id) ON DELETE CASCADE,
  stem_file TEXT, kind TEXT, bars INTEGER, source_offset_s REAL,
  sample TEXT,                      -- v4: the sample row (JSON) a restore inserts again
  fingerprint BLOB,                 -- v4
  removed_at TEXT                   -- v4
);

CREATE INDEX idx_samples_cat ON samples(kind, category);
CREATE INDEX idx_samples_key ON samples(key_label);
```

Schema v7 adds `arrangements (zip_id PRIMARY KEY, bpm, bars, parts TEXT, created_at)`: per part a string with one character per bar (§5.8b).

Schema v9 adds `samples.shape` (§5.8a); `analyze_library` fills it in for older libraries.

Schema v17 adds `reference_tracks (id, rel_path UNIQUE, size, mtime, bpm, key_label, grid_confidence, profile TEXT, error, analyzed_at)`: the tracks in `<Library>/References/`, each with its mix profile as JSON (§5.16, §5.17).

Schema v8 adds `zips.kind`: a pack of loose samples is a row like a zip (code `P0001…`, `original_path` = its folder, `file_sha1` = `pack-` + the SHA-1 of the folder path), its files are its `stems` rows (paths relative to the folder). Zips keep their own numbering (`S0001…`).

Reprocessing a zip deletes that zip's samples (files + rows) and regenerates them. `favorite`, `rating` and `tags` survive reprocessing where a regenerated sample matches an old one by stem + kind + length + offset (nearest, within a tolerance so a moved bar 1 still matches); samples matching a `removed_samples` row are not written at all.

**Changing the library BPM** requires reprocessing loops and FX & fills (one-shots stay). The UI offers a "Rebuild loops at new BPM" action that reruns stretching, slicing and event cutting for all zips. The original zips must still be available (store `original_path`; warn if missing).

**Storage** (Settings): every bass and strings part and every FX stretched to a project tempo is rendered once and kept under `.drumvault/` (bass, strings, tempo; keys, stabs and drones for older tracks' parts), also for generations prepared in the background and never played, so the folders grow as you generate. The section shows how much that is and how much of it nothing plays; **Clean up renders** deletes those (`clean_renders`, after a confirm): everything but what the saved projects, the open project, the shortlist and this session's generations play, and anything made in the last 10 minutes (a render under way). Samples, originals, projects and peaks are never touched. Whatever is gone is rendered (or stretched) again when something needs it. If a project can't be read, nothing is deleted.

**Serum patches with missing samples:** a patch that needs sample files by a path on another computer (a Windows drive, another Mac's home folder or disk) and doesn't carry them is left out of the bass patch pool: Serum plays it without them. A sample embedded in the preset (Serum's "embed in preset": `embedded_audio` beside the path it came from) is there, whatever the path; Serum's own wavetables ("/Analog/…") are found by Serum. `list_presets` reports `missing` per patch; the folder picker says how many were left out. Presets with embedded samples are large (tens of MB): the plugin state is converted with numpy (JUCE base64). The engine's one Serum instance (a second one, loaded off the main thread as RPC calls are, fails in pedalboard) doesn't load a patch again that it already has, and keeps the plugin states of the last 8 patches it loaded, so parts taking turns only pay Serum's own load.

`grid_preview` is not queued behind imports (it runs on its own thread) and answers directly: it sums the zip's drum stems to one mono 16-bit WAV at `grid_preview_sr` in `.drumvault/grid/<zip_id>.wav` and returns its path, sample rate, duration, the zip's BPM, the bar 1 the library is cut on (`bar_one_ms`, and `manual` if it was set by hand) and the stem names. `preflight` and `scan_references` answer directly, each on its own thread (§6.5a, §5.17). `scan_references` with `analyze` measures every new file before it answers (some seconds a track).

### 5.16 Mix profile (`mixprofile.py`)

A whole mix measured: what the pre-flight checks of an export's masters (§6.5a) and what a reference track is remembered as (§5.17). One measurement for both, so a render is held against the references like for like. On the track's grid (its BPM, bar 1 at a given time), bar by bar: the K-weighted loudness (both sides' power summed, as BS.1770 does), the lows (under `profile_low_hz` = 150 Hz) and the power in the arrangement's 24 bands. From those:

- **Full bars and drops.** Given (a generated track's sections: its drops), or found: a bar is full within `profile_full_rel_lu` (−3 LU) of the 90th percentile of the bars' loudness with its lows within `profile_full_low_rel_db` (−8 dB) of theirs. A drop is a run of 8 or more full bars (a gap of one bar bridged) after 4 that aren't, so a track that starts full has no drop there. Measured on eight of the user's own tracks (their stems summed), a stretch of kick and hats is 0.6 to 4.6 LU under the drops, so loudness alone doesn't tell the two apart: such a stretch often counts as full, and the drop is still found where the track comes up.
- **Per drop** its **lift**: its first 8 bars (`profile_lift_bars`) against the 8 before, in LU and in dB of low end. On those tracks a real drop comes up 1.4 to 5.8 LU or 6 to 25 dB in the lows; after a loud, bright build the loudness can even fall (−1.7 LU) while the lows come up 14 dB, which is why both are kept. **Break depth**: the quietest 8 bars between the first and the last drop under the full level.
- **Over the full bars:** the tone in five regions (40–150–500–2000–6000–16000 Hz, the app's `REGIONS`) in dB of the whole, the **width** (sides against middle) and the **low end in the sides** (the same under `profile_mono_hz` = 120 Hz).
- **Of the file:** integrated loudness (BS.1770, gated, pyloudnorm), sample peak and **true peak** (the blocks peaking within 3 dB of the highest sample, 4× oversampled), their difference (`plr_db`), DC, where the sound starts (`head_ms`: the first sample over −60 dBFS) and how it ends (`tail_db`: the peak of the last 10 ms).
- **The DJ's mix-in and mix-out:** over the first and the last 16 bars, how much stronger the lows are in the first 40 % of every beat than in the rest of it (`pulse_db`: a kick on every beat; 4 to 34 dB on the user's tracks, a held bass is 0) and the lows there against the drops'.
- **Bar by bar, for the generator** (§5.17): each bar's lows (`bar_low_db`), whether it is full (`bar_full`, a drop's) and whether a kick plays (`bar_kick`: its lows at least `profile_kick_pulse_db` = 3 dB stronger in the first 40 % of each beat, as `pulse_db`, and within `profile_kick_low_rel_db` = −24 dB of the full bars' lows, so a hat's or a pad's faint lows don't count).

Every number is in `config.py` (`profile_*`).

### 5.17 Reference tracks (`references.py`)

Finished tracks the user drops into **`<Library>/References/`** (WAV, AIFF, FLAC, MP3, OGG; any depth; bought tracks, not previews): each measured as a whole mix (§5.16) and kept as a row of `reference_tracks`. Nothing is cut from a reference and nothing of it is played: only its numbers are kept.

- **Measuring** (`scan_references` with `analyze`): the tempo and the beats from the mix itself (`tempo.detect_tempo`, as a zip's full mix, searched in `reference_bpm_min`–`reference_bpm_max` = 110–150 BPM, whole numbers; a BPM in the file name wins as it does for stems), the key the same way, then the profile with the drops found. A file is measured once and again when its size or date changes; a file taken out of the folder is forgotten; a file that can't be measured (shorter than 30 s, no beat) keeps its reason and doesn't count.
- **Listing** (`scan_references`): `{folder, tracks, pending, summary}`, `pending` the files not measured yet, and those measured before the profile kept the bars' kicks (they still count for the pre-flight until measured again). **Settings → References** shows them (BPM, key, loudness, crest, drops, lift, width), opens the folder and measures the new and stale ones; Create then takes them up at once.
- **The summary** an export is held against: per measure (loudness, crest, lift, break depth, width, low end in the sides, length, BPM) and per tone region the references' median and their range. With fewer than `reference_min_tracks` (3) there is none.
- **Steering the generator** (§6.6): a reference's structure, read from its kick, full bars and loudness bar by bar, is a template beside the zips' (an even share), and its arc (the drops' lift, the break depth) is what the best of 12 is scored on.
- *Not done:* the mix balance, the EQ and the rides still come from the user's own zips (they need stems), and the references are not separated into stems.

### 6.2a Grid view

Sets bar 1 of one zip by ear and eye. All stems of a zip share one timeline (they are never offset from each other), so one offset fits the whole zip.
- A zip picker in the top bar (opens on the first needs-review zip; **Align grid** in the zip panel opens a specific one), with the BPM and number of drum stems.
- **Waveform:** all drum stems summed (engine `grid_preview`), under a fixed grid of bars, beats and 16ths with bar numbers. Dragging the waveform moves the stems against the grid (⇧ for fine moves); ⌘-scroll or pinch zooms around the pointer down to single samples; clicking the ruler or the waveform sets the playhead, which follows playback.
- **Every beat stacked:** the envelope of every beat folded onto one (±15 ms, ±50 ms or a whole beat), with the grid line in the centre and a readout of how far the hits are early or late. Dragging here moves bar 1 precisely.
- **Transport:** Space plays the stems with a metronome on the grid (accent on the downbeat), M toggles the metronome, separate click and drums levels. Clicks not yet heard are rescheduled when bar 1 moves, so a drag is audible straight away.
- **Bar 1:** the offset in ms with −10/−1/+1/+10 nudges (← → and ⇧← ⇧→ too), **Snap to hits** (moves bar 1 to the stacked hits' attack), **Revert**, **Apply & re-cut** (reprocesses the zip with `grid_offset_ms`) and **Use detected** (drops a hand-set bar 1).

### 6.3 Library view

- Filters: kind (one-shot / loop / FX & fills), category, key (multi-select, plus "compatible keys" via Camelot neighbors), bars, source zip, favorites, and text search on filename/tags.
- A virtualized list (thousands of rows): waveform thumbnail from peaks, name, category, key, bars, a favorite star, and a rating.
- **Audition**: click or Space plays the sample, ↑/↓ moves to the next sample and plays it, Esc stops. Loops repeat while auditioning. When the Arrange transport is playing, an auditioned loop starts on the next bar, in sync.
- "Find similar" action: nearest neighbors by fingerprint within the same category.
- Drag a sample out to Finder or Logic (Electron `startDrag`) as a bonus.
- **Cleaning up:** ⌘-click, ⇧-click (range) and ⌘A select several samples; **Delete** / ⌫ removes them at once, without a confirm since they can be restored (engine `delete_samples`: WAV files, peaks and rows). Deleted samples are remembered per zip in `removed_samples`, so reprocessing the zip (also a Grid re-cut or a library BPM rebuild) doesn't bring them back; it re-cuts them into the trash instead, so a restore matches the current grid and BPM. Whole zips are removed from the zip panel (**Delete samples**).
- **Move sound** (selected loop, fill or FX: −1 / +1 in the bottom bar, or ← / →): rotates the sample file a beat earlier or later inside itself, wrapping around (e.g. a fill on beat 3 of its bar moved to beat 4). Engine `shift_sample` rewrites the WAV and peaks and stores the total in `samples.shift_beats`; reprocessing applies it to the new cut (matched like favourites). Arrange clips using the sample change with it.
- **Deleted** (top bar, with a count) lists the deleted samples, newest first: play them, select one or several (⌘/⇧-click, ⌘A) and **Restore** (Enter). Their WAV and peaks wait in `.drumvault/trash/<id>.wav|json`; restoring (engine `restore_samples`) moves them back under their name, or the next free number if a re-cut reused it, with favourite, rating and tags. Deletions from before the trash existed have no file: restoring them only forgets the deletion, and the next reprocess brings them back.

### 6.4 The timeline (mini DAW, in Create)

Create (§6.6) shows the track on screen on this timeline: a generated track or one built by hand. What was the Arrange view; "project" below is a track.

**Project model**
- Project BPM = library BPM (fixed per project, shown read-only).
- Time signature: 4/4 only.
- Length in bars (default 192, editable).
- Saved as JSON `.dvproj` files (default folder `<Library>/.drumvault/projects/`), with autosave.

**Lanes**
- Default lanes: Kick, Clap, Snare, Hats, Perc, Tops, Groove. The user can add, rename, reorder, color (click the colour strip for a palette), and delete lanes.
- Per lane: volume (dB, a bar filled to the level: click/drag to set, double-click for 0 dB), mute, solo, and pan (same bar, filled from the centre).
- **Each lane exports as one stem.**

**Clip types**
1. **Audio clip** (loops): placed on the bar grid. Dragging the right edge extends the clip by repeating the loop (a whole number of loop lengths, or any bar count, ending mid-loop is allowed). Per-clip gain. Optional left trim in whole beats. **Fades:** dragging the top half of a clip's edge (or the fade handle inside it) sets a linear fade-in or fade-out, snapped like everything else; the bottom half still resizes. Fades follow the edges when a clip is resized, never overlap, apply to pattern clips too, and are scheduled in `schedule.ts` (`fadeAt`), so playback and export match. **Move sound** (−1 / +1 in the clip bar, ⇧← / ⇧→) moves the sound a beat later or earlier inside the clip's loop, wrapping around, while the clip stays where it is (e.g. a fill on beat 3 moved to beat 4); pattern clips rotate their steps the same way.
   FX & fills (events) also become audio clips: placed at a bar, they play once over their length; extending one repeats it like a loop.
2. **Pattern clip** (one-shots): references 1 one-shot sample and holds a step grid of 16 steps per bar, pattern length 1, 2 or 4 bars, and 3 velocity levels per step. A pattern clip repeats when extended, like an audio clip. Double-click opens a step editor beneath the timeline. Quick presets: "4 on the floor", "offbeat", "every 2 & 4". A pattern may carry a **groove** (16 step offsets in 16ths and 16 accents in dB, taken from a loop, §6.6): each step lands that much late or early (by its place in the bar) at that accent.
3. **Loop variations** (audio and pattern clips, not bass): **pitch** in semitones, played faster/slower like a sampler; a pitched loop plays as 16th slices that each start on the grid (the same slicing as another tempo, §6.4a), so it stays in time. **Only the first bars** (`loopBars`): an audio clip repeats only its loop's first 1 or 2 bars. Both show in the clip label (`+1 st`, `bar 1`), are scheduled in `schedule.ts` (playback = export) and are set from the right-click menu.

**Editing**
- Snapping follows the zoom: moves and resizes snap to the finest division at least 14 px wide (several bars zoomed far out, bars at the default zoom, then beats, 8ths and 16ths zoomed in close). Hold ⌥ to snap four times finer, down to 16ths.
- Select, multi-select (drag a marquee or ⇧-click), move, copy (⌥-drag), R or ⌘D duplicate (places the copy right after), Delete.
- ⌘Z / ⇧⌘Z undo/redo (command-pattern history in the store, minimum 100 steps).
- **Section markers**: named ranges (Intro, Build, Drop, Break, Breakdown, Outro, custom), drawn in a band above the ruler. Click an empty spot to add an 8-bar section (or up to the next one), or drag to set its range; a name box opens right away with quick picks. Double-click a marker to rename or delete it. Clicking a marker selects all clips in that range, enabling a "duplicate section" workflow. Generated arrangements arrive with their sections named.
- Horizontal zoom (pinch / ⌘ + scroll) and scroll; vertical lane height adjustment.
- Rendering performance: the timeline uses a single canvas (or virtualized DOM) and must stay smooth at 192 bars × 10 lanes × ~200 clips.

**Transport**
- Space = play/stop, click on the ruler = move the playhead, a loop region (drag on the ruler), an optional metronome, a bar.beat position display, and the playhead time next to the total length (m:ss.t / m:ss).
- Playback starts within 50 ms of pressing play.

**Audio engine** (`audio/engine.ts`)
- AudioBuffer cache (LRU, ~1.5 GB cap) decoded from the library files via `file://` reads routed through the preload.
- Lookahead scheduler: a 25 ms timer tick schedules everything in the next 120 ms with `AudioBufferSourceNode.start(when, offset, duration)`.
- Graph: source → clip gain → lane gain → [lane EQ] → [lane compressor] → duck → pan → [mono low end] → lane tail → [drum bus gain] → master gain → destination. A lane with `monoBelow` (the kick's and the bass's in a generated mix, §6.6) has its low end summed to mono after its pan: a 4th-order Linkwitz-Riley crossover (two Butterworth filters each way, adding up flat), the lows mixed to one channel, in playback and in its stem. A lane's sidechain recovers over `duckBeats` (0.6 of a beat unless set). A clip with `echo` sends to its lane's delay (a feedback delay with a high- and a low-pass in the loop, returning into the lane before its volume), a lane with `room` uses a short room as its reverb; a pattern clip with `gate` plays each hit that long and fades it out (§6.9).
- Playback must be sample-accurate: no drift over 192 bars.

**Right-click menu** (Arrange timeline), the same commands as the keys:
- On clips (the clicked one joins or becomes the selection): Cut ⌘X, Copy ⌘C, Paste here ⌘V, Duplicate ⌘D, Delete ⌫; Split here (S splits at the playhead; a split clip plays exactly as before: the loop or pattern carries on); Move sound a beat earlier/later; Remove fades; Edit pattern; Replace with copied sample (copy one clip, then replace the sample of others, keeping place, length and pattern); Swap for a similar sound (the most similar library sample, again for the next); Pitch up / down a semitone, Original pitch; Play the whole loop (a clip on its first bars); Play straight (a pattern without its groove); Show in Library; Reveal in Finder.
- On a section marker: Rename, Duplicate section, Loop this section, Play section, Delete marker (the clips stay).
- On empty space / the ruler: Paste here, Select all, Play from here.
- The clipboard holds clips inside the app; ⌘X/⌘C/⌘V act on clips when no text field has focus.

### 6.4a Project tempo

Samples are cut at the library BPM. A project (Arrange, or a generation) can run at another tempo without changing pitch, like warping in Ableton or Logic:
- **Drum loops, fills and rolls** play as 16th slices: each slice starts on the project's grid with its own piece of the loop (Ableton's Beats mode), so transients and pitch are untouched. Faster: a slice is cut at the next one (3 ms fade); slower: a tiny gap after it. Done in `schedule.ts`, so playback and export match; at the library tempo a loop is one event as before (bit-exact).
- **FX** (risers, downlifters, impacts, sweeps, atmos) would break up when sliced: the engine stretches them with Rubber Band (`stretch_samples`) into `.drumvault/tempo/<bpm>/<rel_path>`, once per tempo, redone only when the sample changes. Playback and export make sure they exist before loading (`audio/tempo.ts`).
- **One-shot patterns** just land on the new grid.
- Clips store their sample's tempo (`SampleRef.bpm`; older projects derive it from the length).
- **Arrange:** the BPM field in the toolbar (60–200) sets the project tempo; positions stay in beats, the playhead stays on its bar. It shows in the accent colour when it differs from the library BPM. A project keeps its tempo when it's opened again, and a generation sent to Arrange keeps the tempo it was generated at.
- **Generate:** a Tempo option: Library (default), Fixed, or a Range from which every track picks a whole BPM (seeded). Remembered between sessions.
- Auditioning a library loop in sync while a project plays at another tempo speeds the preview up or down (audition only, slight pitch change).

### 6.5 Export

- An **Export Stems** dialog: export folder, the project folder's name (default `<Project> - <BPM> BPM - <Key>`, e.g. "Generated 08 - 124 BPM - E minor"; no key on a project that isn't a generation), range (whole project or loop region), format (24-bit or 32-bit float WAV, sample rate = library rate), checkboxes per lane, the **Masters** (on by default) and **MIDI** (on when the track has a bass part).
- **Layout** (as House of Tracks takes it, zipped by the user): the project folder holds `masters/` (`mixdown.wav` and `mastered.wav`; in a track that sings, also `mixdown instrumental.wav` and `mastered instrumental.wav`: every lane but Vocal and Vocal Chops), `stems/` and `midi/`. The vocal takes a track sings are marked used in it once it's exported (`usedIn` in their meta.json): House of Tracks takes each vocal only once.
- **Masters:** `mixdown.wav` is all unmuted lanes, unmastered (the stems played together). `mastered.wav` is made from it by the engine (`master_mixdown`, `master.py`), hosting Ozone 11 like Serum (pedalboard, look-ahead compensated, so it has the mixdown's length and lines up with it): the mixdown brought to −14 LUFS so the chain sees one level, Ozone 11 Dynamics as a gentle glue (RMS, −12 dB, 1.5:1, 30 / 120 ms, every band alike), then the Ozone 11 Maximizer with 50 % soft clip and its ceiling at **0 dB**, its input gain solved pass by pass until the master measures **−6.5 LUFS** integrated (BS.1770, within 0.1 LU) — House of Tracks wants −9 to −5 LUFS and the limiter between −2 and 0 dB. All of it in `config.py` (`master_*`, `ozone_*_plugin`). The first master loads Ozone (some seconds); a pass over a six-minute track takes a few seconds. If it fails (Ozone missing, a silent mixdown), the rest of the export is written and the dialog says why; it shows the master's loudness and peak when it's made. A user-made Ozone chain is to replace the basic one.
- Rendering: one `OfflineAudioContext` per lane, from bar 1 to the end bar; the same scheduling logic as live playback (shared code, not duplicated). Muted lanes are skipped; solo is ignored.
- All exported files have **identical length** and start exactly at bar 1, so in Logic you import them at bar 1, set the project to the same BPM, and everything lines up.
- File names: the lane's name (`stems/Clap 2.wav`); two lanes of the same name get a number. MIDI files are named as their part's lane (`midi/Bass.mid` next to `stems/Bass.wav`): only the bass, not stabs or drum patterns.
- Clipping check: if any lane peaks above 0 dBFS in 24-bit mode, warn and offer 32-bit float or auto-gain.
- **info.txt** at the top of the project folder (with every export that writes something): the title (the folder's name), BPM, key ("E minor"; "none") and length ("5:10 (160 bars)"), then **About the track** (`describe.ts`, read from the project as exported: the lanes that play, its sections and rules): what kind of house it is (its character: dark and dubby, bright disco, stripped and percussive tech house, deep and warm; else "club house") and what it's built around, what it's made of (the bass, the stabs, the drums' layering, ride, disco hits, strings and where, the breakdown pad or reese, the bed, the vocal and where it sings), its DJ layout (bars, intro and outro, drops, breakdowns), and three labels whose sound it sits with, by its character (disco: Glitterbox, Defected, Toolroom; deep: Defected, Freerange, Classic Music Company; dub: Hot Creations, Moon Harbour, Fuse London; percussive: Toolroom, Solid Grooves, Repopulate Mars; else Toolroom, Defected, Hot Creations; a gospel or soulful made vocal puts Defected first), and **Tags:** the three of House of Tracks' tags (its upload form: Aggressive … Work out, `HOT_TAGS`) that fit it best (`houseTags`, scored from its character, lead, key, layers and vocal: every track is Club and Groovy, outscored by what sets it apart: Dub and Dark for a dubby one, Funky, Happy or Summer for disco, Raw for a stripped one, Soulful for a deep one or a gospel or soulful vocal, Melodic for stabs taking turns or strings, Uplifting for a major key or an uplifting vocal, Heavy Bass for a reese; ties in the form's order). Then **Vocals**: for each vocal the track sings, a Splice loop's file, its pack and label and the pack's link, or a made vocal's lines and "AI-generated with ElevenLabs (voice, mood); lyrics written for this app"; "Vocals: none" for a track that doesn't sing.
- "Reveal in Finder" after export.
- *Implementation notes:* event start times and sample offsets are snapped to whole sample frames, so a stem is a bit-exact copy of the placed samples (live playback uses the same snapping). Lane gain nodes are upmixed to stereo before the pan node, so a mono sample panned centre plays at unity rather than −3 dB. Exporting the loop region gives files that start at that region's first bar; the MIDI files use the same start.

### 6.5a Pre-flight: the masters checked before they go out

The critic and the mix check in Generate (§6.6) work from what was measured of the samples. The pre-flight listens to the result: after the masters are written, the engine (`preflight`, `preflight.py`) profiles `mixdown.wav` and `mastered.wav` (§5.16) on the project's grid, the drops taken from a generated track's sections (found from the audio in any other project, or once the track was made longer or shorter in Arrange), and the Export dialog shows the checks, what is wrong first, over the track's loudness bar by bar with its drops lit. Each check is **ok**, **warn** or **info** (a number with nothing to hold it against). It changes nothing and writes nothing; the export stands whatever it says. Without a master (Ozone missing) the mixdown alone is checked.

| Check | Warns when |
|---|---|
| Loudness (master) | integrated loudness outside −9 … −5 LUFS (what House of Tracks takes) |
| True peak (master) | over +1 dBTP between the samples |
| Limiting | the master lost more than 12 dB of crest against the mixdown (on the user's tracks an unmastered mix stands 14.7–16.7 dB over its loudness, a master at −6.5 LUFS about 7: some 9 dB is the chain's ordinary work) |
| Drops after mastering | the master takes more than 1.5 LU off how much the drops come up |
| Drops land | a drop is neither 1 LU louder nor 3 dB heavier in the lows than the 8 bars before it |
| Low end in the middle | under 120 Hz the sides are over −12 dB against the middle |
| DC offset | over −50 dBFS |
| Starts on bar 1 / Ends clean | the first 30 ms are silent / the last 10 ms are over −40 dBFS (whole-track exports only) |
| Mix-in / Mix-out | no steady kick through the first / last 16 bars: the lows under 3 dB stronger on the beats, or more than 15 dB under the drops' (whole-track exports only) |
| Key | the mix reads (key.py) as another key than the track's, with confidence 0.6 or more; its relative key, or a read with less confidence, is info |
| Tone / Width against the references | with 3 or more reference tracks (§5.17): a region more than 3 dB (the width 4 dB) from their median **and** outside all of them; info without references |

The thresholds are in `config.py` (`preflight_*`). *Not checked:* clicks inside the track (a kick's own attack looks like one), and the instrumental masters.

### 6.6 Create: generating tracks (Phase 5)

The page the app opens on (sidebar: **Create**; Generate and Arrange were merged into it). It instantly builds complete, DJ-friendly drum arrangements from random combinations of the library and puts them straight on the timeline (§6.4), so you cycle through tracks fast, listening as you go, and change what you like in place: move, cut and duplicate clips, remake a lane, change a choice. The goal is range: no two generations need share a structure, a build style or a kick treatment.

**Layout:** the top bar (‹, **Generate**, the track counter, ★, the track's name and whether it's saved, **Saved ▾**, **Options ▾**, **Export…**), the transport bar (undo/redo, play, position, loop, click, the track's BPM and length, zoom, **Fit**, **Library**, **Panel**), the lane headers and the timeline, and the side panel (below). A track put on screen is zoomed to fit the window. An empty track shows where to start (Generate, or the Library to build one by hand).

**Keeping a track** (`useProject.scratch`): a generated track is a scratch track until it's kept, and only then saved (`<Library>/.drumvault/projects`, "Generated 01", …, autosaved from then on). It's kept by an edit by hand on the timeline (a clip moved, cut, added, a lane renamed or deleted, the tempo or length changed, a name typed), by ★ / ⌘S, or by exporting it. What the generator's controls change (a lane remade, a new sound, a choice, a module, the lane mix: volume, pan, mute, solo, sidechain) keeps a scratch track a scratch track; it's still an edit of the track (⌘Z). **Saved ▾** lists the saved tracks (opening one puts it in the history), **New empty track** (to build one by hand: kept once something is put on it) and **Delete this track** (or Discard, for one not saved). The shortlist of before (`.drumvault/shortlist.json`) was moved into saved tracks once: the file keeps its items under `migrated`.

**Cycling**
- **Generate** (G) makes a new arrangement (the best of 12, below) in well under a second and starts playing it right away (from the start, or from the same section you were listening to). ← and → (with no clips selected) go through this session's history, → making a new one at its end; each track comes back as it was left (its edits, and its file once saved; ⌘Z history starts again). Tracks are kept until the app quits.
- Space plays/stops; 1–9 jump to a section; the sections are the timeline's markers.
- Shown per generation: length, BPM, the track key, its structure (e.g. "Intro 32 · Build 16 · Drop 32 · Break 8 · …"), the variation choices made, and which zips the samples come from.
- **Keep**: a 🔒 on every lane with a sound of its own (Kick, Clap, Hats, Perc, Tops, Groove, Bass, Stab, Disco Hit) keeps it on the next press of G: a drum lane its main sample, Bass its part and patch, the stab lanes (together) their samples, rhythm and turns, the disco lanes their hits. The key and the structure have a 🔒 of their own in the track details. Everything not kept is made again.
- **Side panel** (on the right, **Panel** in the transport opens and closes it): the **Track** (length, BPM, the key, the structure, the Choices below, what else the track did, its zips and seed), one module at a time (Bass, Chords, Vocals, Strings, Pads, Ambience, Disco Hits, Reverb builds; pills at the top, each module's with its on/off switch, so a module is switched on or off for new generations without opening it), or a lane. A lane's ⋯ in its header opens its module (Bass → Bass, Stab, Stab 2, Stab 3 → Chords, Strings → Strings, Disco Hit → Disco Hits) or, for the drum and FX lanes, the lane itself: its sounds (with play) and the choices that shape it. Every lane on the panel has **Keep**, **New sound** (other samples of the same kind where the lane plays, the clips staying put: a clap for a clap, a fill for a fill that ends the same way, tonal FX only in a key that fits; another patch on Bass; another string sample where the strings play) and **Remake** (the lane header's ✦). The panel remembers what it showed. A track built by hand has no Track, modules or choices.
- **Choices**: the track rules a producer would decide on (`choices.ts`), grouped (Drops: the bar before them, silence, kick, build-up and its length, crashes into them, fill, riser, mix high-pass, drop 1 · Breakdowns: the groove carried through or not, perc, tops, hats, bass, stabs · Builds · Intro & outro: hats, bass, claps, perc, lift · Every 8 and 16 bars: crash, four kicks out, fill, clap rolls · Sound: ride, FX density), each a menu showing the track's value. Changing one makes the lanes it shapes again with it, from where the track's random stream was once its structure and key were chosen (`Generation.rngAt`, a "replay") and with its samples, so what doesn't follow from the rule comes out the same; the rest of the track stays as it is (⌘Z goes back). On a kept track it asks first (your edits on those lanes are replaced); the key menu does too. The 🔒 next to it locks the value for every next track (`GenerateOptions.locks`, remembered), over what a track draws or a real track does; changing a locked one moves the lock. Choices that don't apply (stab rules on a track without stabs, breakdown rules without breakdowns) aren't shown. The other things the track did are listed below them.
- **Options ▾** (for new tracks; the track on screen keeps its own): length range (default 4–6 min), tempo (§6.4a), sources (all zips or a selection), favourites/ratings bias (on), **Listen back** (on: the critic below). The same seed + library + options gives the same generation.
- **Volume** slider in a generated lane's header (⌥-click or double-click: 0 dB): it changes the track on screen at once (no re-roll), the scratch tracks of the history and the next ones too, and is remembered between sessions (per lane: Kick, Clap 2, Tops 3, …). 0 dB is the balanced mix (the mix balance below); a lane whose samples aren't measured yet plays at its step in the starting mix from before the balance (the kick at −2 dB, Clap −3, Hats −6, …, `LANES.startDb`), which is also the step layers keep under the lane they layer.
- **Per lane, in its header:** 🔒 (Keep), ✦ Remake, ⋯ (the side panel), M and S (mute and solo, kept by lane name while cycling), pan, sidechain. Remake: that lane made again, the rest of the track exactly as it is. It gets a new sample (not one already in the track) and draws the lane's own track rules again: how often the crash comes (every 8 or 16 bars, into breakdowns, into the outro), where the kick drops out, clap rolls and ghost notes, how many tops and when they come in, fills into which parts, FX density, the bass in breakdowns and builds. The structure, key, tempo and track-wide rules (the silence before drops) stay, so the new lane still fits. On the Bass lane it also picks another bassline and/or patch. It's an edit of the track (⌘Z goes back; your edits on that lane are replaced), swapped in at the playhead while playing. Drops can also crash every 8 bars (a rule of its own).
- A track keeps its generation (`Project.generation`: structure, key, rules, picks, bass), saved with it, so its lanes keep their modules when it's opened again. A bass edited with the timeline's own tools (piano roll, a saved bassline) is what the panel shows and keeps. A renamed lane loses its module.

**Structure: a real track's, changed a little, or the grammar**
Most generations (80 % when the library has arrangements, §5.8b) follow a **real track's** structure and the decisions its producer made, about 90 % of the way (`template.ts`):
- The track's arrangement is read phrase by phrase: no full kick = breakdown; kick with the bass full or near the track's highest energy (the full parts that play) = drop; the first four phrases before the first drop the intro, more than that a build; after the last drop the outro; a quieter kick part after a breakdown builds into the next drop. Sections are kept within the limits below (an intro of 48 bars becomes 32) and the generator's grammar (a build runs into a drop); a track that ends on its drop gets its last 16 bars as the outro.
- Its rules where they can be read: hats in breakdowns, hats in the intro and the outro (none, the half next to the drops, all through), claps and perc in the intro, when the top loops come into the intro, top loops in breakdowns (low-passed as dark as measured, open, or out), bass in breakdowns / builds / intro (high-passed or out; the high-pass from how much brighter the bass measures outside drops: 120 Hz · 2^octaves, 150–450 Hz), the breath before drops (the tops, or the tops, claps, hats, perc and bass, out in the bar before them in most drops), the ride (later in drop 1 and/or the later drops), four kicks out before drops, crashes every 16 and every 8 bars, fills into 16-bar marks and drops, FX density, the breakdown kick (out, thin/filtered when quiet).
- Then made new: each rule read is drawn again with a chance of 12 %; one section a phrase longer or shorter (60 %); sometimes another breakdown kick or build style; always at least one change. Fitted to the length range only when outside it. The choices list starts with "structure after S0012 (drop longer, …)".

**Or a reference track's** (§5.17; `templateFromReference`): with reference tracks measured, the 80 % are shared evenly between the zips' arrangements and the references (all of it the references' when there are no arrangements). A finished mix has no stems, so less of it is read: phrase by phrase on the grid of its first drop (a track's phrases needn't start on its bar 1), no kick through most of a phrase = breakdown, full = drop, a kick without that = intro (the first four phrases before the first drop) or build, after the last drop the outro; then the same grammar and limits as above. From it also: the kick in its breakdowns (out when it plays in under 15 % of the bars, else high-passed or filtered), a build rising (its second half 2 LU or more louder than its first: layered or double time), and the kick out in the bar before its drops (`dropKickOut`). Everything a mix doesn't tell (hats, tops, bass, the breath, …) the generator draws; its sections carry no `src`, so rides take like sections of the zips. Made new the same way. The choices start with "structure after the reference “Name” (…)". Profiles measured before the bars' kicks were kept give no template.

Otherwise an arrangement is a sequence of sections, each a whole number of 8-bar phrases, generated from weighted rules and then fitted to the chosen length. Hard constraints only where DJs need them:
- **Always:** a mix-in intro and a mix-out outro of ≥ 16 bars each, with a steady kick (beatmatchable, nothing tonal) and hats by the track's rule (none, the half next to the drops, or all through; more often in the outro); the kick there is subtly high-passed (60–110 Hz) so it mixes over another track, and top loops come in (intro) and thin out (outro); the track starts and ends on a bar line. **Never the kick alone:** wherever an intro or outro would have the kick with nothing but FX or a crash (no hats yet and the tops coming in halfway, or the outro's tops gone; 36 in 400 before), the hats play with it (else the first top loop, else the perc); a drum fill with the kick counts as company, and the breath and the silence before a drop stay as they are.
- **Halfway is on a round's line** (`halfwayBars`, `structure.ts`): sections are counted in rounds of 16 bars, and wherever something changes halfway through a section (a drop's loops switching, a disco hit, the vocal's or the strings' half, the ride coming in late, the lean drop's layers, a double-time build's second half, the intro's and outro's halves) it is on the 16-bar line nearest the middle, of two as near the earlier: a 48-bar drop changes after 16 bars and plays 32 more (2 and 4 phrases, never 3 and 3), a 40-bar drop after 16, a 24-bar section after 16. A section of one round changes on its 8-bar line.
- **Everything else varies.** Examples of what the rules can produce:
  - Intro → build → drop → break → drop → long break → drop → outro (the classic shape).
  - One long breakdown in the middle, or three short ones (no "false drops": every breakdown runs into a real drop or the outro).
  - Two or three drops of 16–48 bars; drops that change their top/groove halfway.
  - Builds of 8–32 bars: layered slowly one element per phrase, all at once, or in **double time** (hats/perc/snare density doubling 8ths → 16ths → 32nds towards the drop).
- Weights favour the classic shape, so most generations are sensible and some are surprising.

**Identity: a character and a lead** (`character.ts`; an RNG of its own; tracks made before have neither)
- **A character** (rule `character`, every new track): dark and dubby, bright and disco, stripped and percussive, or deep and warm. Each sets the rules that make it that kind of track, over what the track drew on its own (a real track's own decisions, a kept rule and a lock go over it): **dub**: sparse FX, a stab delay throw every 8 bars, the stab filter opening over every drop (not with a stab loop, whose filter opens before them), dark breakdowns (the groove held at 450–800 Hz, 5–8 dB down), strings in the breakdowns, stabs and bass through the breakdowns filtered, the ride from the second drop, no 8-bar crashes or clap rolls. **disco**: busy FX, disco hits, two or three stabs saying the turn twice, strings in the second half of drops, crashes every 8 bars, the ride all through, clap rolls, fills every 16 bars. **drums**: no strings or disco hits, one stab resting a phrase and growing through drop 1, the second perc from drop 1, three top loops, a kick variation every 8 bars, ghost claps, the perc through the breakdowns. **deep**: strings from the second drop, stabs and bass through the breakdowns filtered, normal FX, the ride late in drop 1, stabs at 900–1500 Hz turning by leaving their last stab out, the groove held softer. The choices start with it ("dark and dubby, led by the stabs: …").
- **A lead** (rule `lead`): the one element the track is built around, drawn by the character's leaning (disco mostly the stabs, drums mostly the percussion, dub and deep the stabs or the bassline), and none when the track lacks the part drawn. The lead is **teased in the intro** (stabs: the tease; bass: high-passed in the intro and outro; perc: in the intro), **in the clear in the breakdowns** from their second part (`breakShape`: from halfway, after the strip): the stabs unfiltered in their own rhythm with a delay throw at the end of each phrase, the bassline in full with no kick over it, the perc open 2 dB under its drop level as the thread; and sits **a little louder** (stabs +1.5 dB, never over the kick less 1; bass +1; perc +1.5). A track led by its stabs keeps a top loop less, for room. The choice Sound → **Lead** changes or removes it. 8-bar variations leave a breakdown with the groove carried through alone (its shape is its change).

**Picked as a record** (`palette.ts`; every new track)
- **One palette around the kick.** Every drum sample is measured against what is usual for its kind in the library (a hat against hats): its **brightness** (the power-weighted mean log2 frequency of its `tone`) and, for one-shots, its **compactness** (`compactness`, §6.6 Punch), as z-scores (the median 0, ±1 about one spread away; a kind needs 4 measured samples). The character sets where the palette leans (dub −0.8 bright / −0.3 compact, deep −0.5 / −0.2, drums +0.2 / +0.8, disco +0.6 / +0.3); the kick is picked by that, and is the anchor: the palette is pulled halfway to where the kick sits (`ANCHOR_PULL`). Claps, hats, perc, tops, groove, ride and crash are then picked by how near the palette they sit (a Gaussian, width 1 spread; compactness counts half): of the candidates, those within 0.7 of the best stay, before the zip spread, weighted by the fit squared. So the zip spread still holds, within the samples that fit. On the user's library: a dub track's drums sit 0.53 spreads darker than usual for their kind, a deep track's 0.35, a disco track's 0.36 brighter. The palette is stored with the track (`rules.palette`); the choices say "drums picked as one palette around the kick (dark and soft), loops picked to interlock".
- **Loops as a set that interlocks.** The loops are picked in turn (the main top loop, the groove, the hats, the perc, the other top loops, then the second hats and perc and the ride), each also by how it interlocks with those already chosen (`interlockFit`): 1 − stack × (0.35 + 0.65 × mask) over each of them, with the critic's measures (`stackOf`: hits on the same 16ths; `maskOf`: the same tone). A loop on other 16ths fits; one on the same 16ths in the same tone is the critic's clash, and is now mostly not picked in the first place. On the user's library the main loops interlock at 0.69 against 0.53 for a loop drawn at random. Samples not measured count as halfway (0.5): nothing is held against them.

**The arc: one element held for the last drop** (rule `hold`; an RNG of its own; tracks with two drops or more)
- The peak is the last drop (it already adds a top loop). One more element is kept out of everything before it, so the peak has something the track hasn't played yet: the ride, the second perc, the second hat loop or the groove loop, by the character's leaning (dub mostly the ride, disco the groove, drums the second perc, deep the ride or the second hats; sometimes none). It must play in the last drop and somewhere before it (else the next one the character leans to is held). The choice Drops → **Held for the last drop** changes or locks it. The choices say "the groove loop held back for the last drop". On the user's library about 7 in 8 tracks hold something.

**Variations of its own** (rule `gestures`; an RNG of its own)
- Instead of a new kind of change at every 8-bar mark, each track has a small vocabulary, drawn by its character from the seven (a kick variation, the hats stopping, a layer out, a loop playing another part, a clap ghost, a fill, a high-pass lift): **two small ones** for the marks every 8 bars, **a medium one** at 16 bars into a section, **a big one** at 32 (with the medium one on top). At each mark the vocabulary's own weigh 6× more, the rest a quarter; where the arrangement changes by itself nothing is added (as before). Repetition is the identity: the same gestures come back through the track. Leanings: dub a layer out, a loop playing another part, lifts; disco clap ghosts, fills, lifts; drums kick variations and the hats stopping; deep loop parts and lifts. The choices say "14 variations of its own: a kick variation or the hats stopping every 8 bars, a clap ghost at 16, a fill at 32".

**Best of 12** (`score.ts`)
- **G** makes 12 candidates (the seed drawn, then 11 derived from it), each listened back to by the critic, scores them, and plays the best. A typed seed makes exactly that track; the winner keeps its own seed, so typing it makes it again. The next track is prefetched in the background one candidate at a time (each takes 18 ms on the user's library, 51 at most: under the playback's 120 ms look-ahead), so the playing track isn't interrupted; all 12 take about 0.2 s.
- **The score** (0–100), from what is measured before anything is rendered: the critic's penalty after its fixes (35 %: 1/(1 + penalty)), how little the loops playing together in the drops land on the same 16ths (20 %: 1 − the mean stack), how well the drum picks sit in the palette (20 %), and **the drops landing, predicted** (25 %): every audible lane's power (its clips' measured energy, its level and volume) over each drop's first 8 bars against the 8 before; a drop lands from 1 LU, and a lift of 3 LU or more counts in full (the pre-flight's check, §6.5a, made on the plan). Unmeasured parts count as halfway. The choices start with "best of 12 (score 85): no clashes, loops interlock 0.40, palette 0.95, every drop lands (+1.7 LU at least)". On the user's library the median score goes from 76 (the first candidate) to 84, and the share of drops predicted to land from 68 % to 94 %.
- **The arc, with reference tracks** (`Generation.arc`): the track's target is the reference its structure follows (its median drop lift and break depth), else the references' median (from one reference on, so every candidate has one and they are scored alike). Predicted on the plan as the engine measures a mix: the drops' median lift as above, and the break depth, the drops' power against the quietest 8 bars between the first and the last drop. Each is a Gaussian on the difference (width 2 LU for the lift, 3 LU for the depth), their mean the arc fit (0…1); it weighs 20 % and the parts above share the other 80 %. Kept with the structure (a lane made again, a choice changed, the structure 🔒). The choices say "arc 0.91 against the reference “Name” (lift +2.4 for +3.0 LU, breaks 8.2 deep for 9.0 LU)". Rendered parts (bass, strings, vocals) count at their render level, as in the balance, so the plan's arc is an estimate; the pre-flight checks the render.
- Not in the score yet: the bass, strings and vocal renders (measured only once rendered), and what the user keeps (stars, skips).
- Tracks made before the arc and the variations of their own (a shortlisted one, a project sent to Arrange) keep going without them when a lane is made again or a choice changed: nothing else in them changes.

**Track rules: random between tracks, consistent within one**
Every variation below is decided once per track and applied to every section of the same kind, so a track has its own logic and doesn't feel random: if drop 1 has a crash (or four kicks out, or a fill) every 16 bars, so does every drop, and the intro and outro crash on the same 16-bar rule. All drops share the kick variation at 8-bar ends, clap ghost notes and rolls, the number of top loops (the last drop adds one), when groove and the second perc come in, and the halfway loop switch. Every way into a drop is the same (four kicks out or just the last kick, roll or fill, riser, impact, the beats of silence, a crash on the 1), and so is every way into a breakdown. One fill, roll, riser, impact and downlifter sample per track, reused (another only where it doesn't fit). The outro mirrors the intro: tops, claps and perc leave the way they came in. Breakdowns choose their own kick treatment; their drums are the track's own, carried through (One groove, below).

**One groove: the drums carry through breakdowns** (rule `glue`, on for every new track; the choice Breakdowns → Groove switches a track back to "each breakdown its own": hats, perc, a top loop and a soft clap by rule or by chance, starting and stopping on the lines. Tracks made before are remade that way.)
A breakdown is the part before it in a darker state, not other content: the same loops and one-shots, in phase, each part moving a step at a time and across the lines. An RNG of its own draws the track's values.
- **What stays** all through, by the track's rules: the perc low-passed (`gluePerc` through 3 in 5, at `glueHz` 500–1400 Hz), the hats thinned (`hatsInBreaks`: high-passed at 900 Hz), the first top loop (`topsBreaks`: low-passed at `topsBreakHz`, or open and only quieter). One part always stays, the **thread** (perc, else hats, else the top loop, whatever the rules say), so no bar of a breakdown is without a timekeeper. What stays closes over the first 4 bars after the line (its filter from open to its cutoff, its level down to `glueDb`, −3 to −7 dB), holds, and opens up again to full over the last `glueOpen` bars (8 or 16, at most half the breakdown) into the next part: the opening is the build. Into an outro it holds to the end.
- **What leaves:** every other loop that played up to the line (the second hats and perc, the other top loops, the groove, the ride, and the hats, perc or top loop when the rules take them out) plays on past it, low-passed from 6 kHz down and fading 16 dB, one after the other: the first over `glueOut` bars (4 or 8), each next one 2 bars sooner (2 at least). Over the 2 bars before the line they already close from open to 6 kHz, except the top loops and the groove: they play full to the end of the drop (no low-pass while a drop plays). The clap goes on soft and low-passed for 2 bars, softer for 2 more.
- **What comes back:** up to four loops the next part starts with (hats, perc, top loops, groove; the main ones first) come in before its line, low-passed and opening, rising from −16 dB: the first over `glueOpen` bars, each next one 2 bars later. The breath and the silence before a drop still cut them, as they do everything.
- **Every later breakdown is the first taken further:** its cutoffs at 0.7 of the one before (never under 250 Hz), 1.5 dB lower, the leavers gone 2 bars sooner. **The long breakdown** strips down to the thread alone for its middle (when that is 12 bars or more): the other stayers fade out after closing, the thread goes darker still, and they come back with the opening.
- The kick keeps the breakdown's own treatment, the bass and the stabs their rules. Rides from a reference track and the mix high-pass leave these clips alone (they have their filter). The choices say "the groove carries through breakdowns: perc and tops filtered, the rest fading out over 4 bars, opening up over 8". Constants: `GLUE_*` in `generator.ts`.

**Variation dimensions** (each chosen per generation as one of the track's rules; breakdowns per section)
- **Kick in breakdowns:** fully out; thin (high-passed at 180–350 Hz, the common filtered one); low-passed (fixed or sweeping open into the drop, kept rare); kept. A kick plays four to the floor (or faster, in a build-up) or not at all: no half-time kick, and none only on the downbeat of each bar (both sounded off; tracks made with the downbeat kick keep it).
- **Announcing parts:** usually the last bar before a drop has no kick (four kicks out), and inside drops the bar before bar 17, 33, … often too; the next bar starts with a crash. Most tracks also go silent for one or two beats right before each drop, except FX, fills and hits (risers, rolls and impacts ring through).
- **The way into drops, the same into every drop** (rule `dropIn`, an RNG of its own, every new track): **straight in** 3 (everything leading in runs up to the line, no silence), a **gap with the drum fill alone in it** 3 (`dropInBeats`: 1 beat 2, 2 beats 3, a bar 1; every lane but the fills, the hits and the bed under the track goes silent there, the risers too: one that stops with the gap is preferred, any other is cut by it; the drum fill runs on through the gap into the 1, and a track with a gap always has its fill into drops unless the fills are locked out), or a **gap with only the FX pulling in** 2 (the same beats; the risers, sweeps and fills ring through it, they run up to the line). `dropGaps` holds the gap for every drop. The choices say "straight into every drop", "2 beats of silence before every drop, the drum fill alone in it" or "… with only the FX pulling in". Tracks made before keep the producer's moment below (`dropIn` null).
- **The big build into the drops after the long breakdown** (rule `bigBuild`, an RNG of its own: big 3, as into the other drops 2; tracks made before: as into the other drops). The drop after the long breakdown is the track's biggest (most often in the middle); every drop after it before the next drop is one (`mainDrops`). Its build runs over the last `bigBars` of the parts before that drop, reaching back into the long breakdown when a build between them is shorter. **How long and what drums, as the user's tracks do** (`mainBuildOf`, template.ts): back from the drop after its longest breakdown while its fills play (a bar without them allowed), else while its FX play at full, as 4, 8 or 16 bars, and whether its kick and its claps are back in that build (a quarter of its bars or more). A track built on a real track builds as that track does; the others like one of the user's tracks drawn at random (their spread of lengths: 19 of 41 build 16 bars, 20 build 8, 2 build 4), the kick and the claps back as often as in them (17 and 18 of 41); without 3 that show it, 8 or 16 bars. Then:
  - **The drums, layered:** claps (`bigDrums`: claps and a snare 3, claps 1.5, a snare 1.5) on the beat over its first half, in 8ths over the third quarter, in 16ths over the last, from −9 dB, low-passed from 1.5 kHz opening to 18 kHz (the clap layers out there); a snare on the Build-up lane joining halfway (from the start without claps): a roll in 8ths then 16ths, or steps 4ths → 8ths → 16ths (`bigSnare`), from −12 dB, low-passed from 350 Hz opening. A track whose fill into drops is a roll sample builds claps under it, no snare of its own. The kick (`bigKick`): out over the build, back four on the floor over its second half (low-passed 160 Hz → 2.4 kHz, from −6 dB), or a roll over its last quarter (8ths, 16ths in the last bar); the bar before the drop as the track's kick rules do it. Over the mix high-pass's bars (below) the build's drums and the breakdown's kick thin out (a high-pass sweeping up in place of their low-pass: a clip has one filter). No pitching up.
  - **Risers stacked** (`bigRisers`: 3 3, 2 2), each ending on the drop, in the key (a noise sweep in any): a long one over the whole build on FX (at least 0.6 of it when the library has one), a riser over about its second half on FX 2, and a short lift (1–2 bars, or none) into the 1 on **FX 3** (a lane of its own, levelled like the FX: hit for hit, 8 dB under the clap's hits, trimmed to its main sample, low-cut at 120 Hz, never high-passed by the mix, ringing through silences like the FX).
  - **Effects** (`bigVerb`: its drums 1, the stabs 1, its drums and the stabs 2, its drums and the top loops 1.5, all 2 (drums, stabs, tops, vocals)): the build's drums send to the lane's hall rising (the square of the way through) to 0.85 on the drop, with reverb builds on (the module), and throw a delay on the last bar of each 4 (0.3, the last bar 0.5); the stab loop announces the drop over the whole build in the part before it (instead of 4 or 8 bars); the top loops and groove, and the vocals, rise into reverb over the whole build (to 0.85, with reverb builds on). The drop comes in dry.
  - **The mix high-pass** over its last 4 or 8 bars (`bigHp`: as the other drops 2, 4 2, 8 1.5) when that is longer than the track's, and **crashes coming faster** over its last 4 bars (`bigCrash`, 6 in 10: every bar, half bars, quarters, 8ths, louder bar by bar).
  - The other drops keep the track's usual build-up, risers and crashes. The choices say "the big build into the drop after the long breakdown: 16 bars, claps and a snare roll, the kick back in its second half, three risers, reverb and delay on the drums, stabs, the mix high-passed over 8 bars, crashes coming faster"; each rule is a Track choice under Builds ("Build into the main drop", "Main build length", "… drums", "… snare", "… kick", "… risers", "… effects", "… high-pass", "… crashes").
- A lane made again never brings a sound another lane plays already (the FX layers of a drop are different risers).
- **One moment into every drop** (the producer's; tracks made before the way into drops): an event is placed by its body, so the silence its producer left before the line (its shape's `gap`) comes with it. Everything leading into a drop stops together: the riser decides (or, without one, the fill or roll), and the fill or roll and any second FX layer must agree with it: all run up to the line (gap ≤ 1 16th), or all stop early within 2 16ths of each other. Never one riser into the drop and another, or the fill, leaving a beat of silence. A riser the track's fill can stop with is preferred, so the track keeps one fill. When they stop early, the rest of the track (every lane but fills, FX and hits) goes silent there too, up to 2 beats; when they run up to the line, the track's own beat or two of silence applies and they ring through it. Events silent for more than 2 beats before their line (a hit on the 1 and a rest, cut from a fill stem) never lead into one. The measured stops per drop are stored with the rules (`dropGaps`) and kept by lane re-rolls, so a re-rolled FX or fill lane stops where the rest of the track does (or the re-roll finds nothing new). Libraries without shapes count every event as running up to the line.
- **Layered FX:** in normal and busy tracks, often a second FX layer into drops (lane FX 2): a riser or a sweep/other FX that measures as rising, never two of a kind from two tracks: another length (a long build with a short lift on top), another texture (noise with a tone), or the same track's. Sometimes a downlifter as the drop hits, next to the impact (on a lane free there: FX lanes never stack sounds). Tonal FX stay in key when the library has any in key, even if that leaves no layer.
- **The producer's own FX:** events of one track that lead into the same bar of it (bodies ending there) or start on it (an impact, a downlifter) were layered there by its producer. Half the tracks (when the library has such moments with a riser in key) take one moment as their FX into drops: its riser(s), fill or roll, impact and downlifter are the track's picks for those jobs, and the rules follow it (a roll if it had one, the impact, two layers if it had two risers). Its own track's moments are preferred when the structure is that track's.
- **Crashes** (their own lane) on the 1 of key moments: every drop, after a four-kicks-out bar, where a ride comes in, usually the outro and sometimes a breakdown.
- **Build-ups** (rule `buildup`, own RNG; in about 7 in 10 tracks): programmed on the **Build-up** lane over the last 2, 4 or 8 bars before every drop (`buildupBars`, the same for every drop; at most half the section, a quarter of an intro), each louder towards the drop (a volume ride bar by bar up to 0 dB): a **snare roll** in 16ths, low-passed and opening (350 Hz → 16 kHz), then high-passed (60 Hz → 1.8 kHz) over its last quarter, velocities soft → full; a **snare** in quarters, then 8ths, then 16ths (thirds of the build-up); a **kick roll**, the track's kick low-passed (160 Hz → 2.4 kHz) in 8ths, the Kick lane out there; **claps on every beat**, the track's clap, the clap lanes out there. The snare is a snare one-shot that isn't one of the track's claps (a clap otherwise). A build-up takes the place of a roll sample (`dropFill` roll becomes a fill), except when the roll is locked; a fill and a riser can still lead in with it. It stops for the silence before the drop like the other drums. Remake on the Build-up lane: another kind and length, another snare, made from the track's `rngAt` so the kick and clap lanes follow. Tracks made before build-ups are remade without one.
- **Crashes into drops** (rule `buildupCrash`, its own choice, in about 4 in 10 tracks): none, coming faster (the 3 bars before each drop: every half bar, every beat, every 8th, −6 / −3 / 0 dB), or on each of the last 4 counts.
- **Into the first drop and out of the last** (own RNG, so tracks are otherwise the same; tracks made before are remade without them): the **lift** (rule `ioLift`, about 8 in 10 tracks): the intro fills up over its last 8 bars (16 in an intro of 32 or more) with what the drops have and it doesn't yet by the rules above, one by one on 4-bar steps, in this order: hats, perc, a second top loop, claps (soft). The outro lets them go the same way from its start. Never the bass or anything tonal (DJ friendly). **Drop 1** (rule `firstDrop`, leaner in about 3 in 4 tracks): a first drop straight after the intro starts leaner and is full by halfway: the clap layers and the second hat loop come in after its first phrase, its last top loop, the groove and the second perc halfway. The later drops are full from their first bar.
- **Top loops in breakdowns** (as in most real tracks): the first top loop plays on, low-passed (900 Hz–5 kHz, or as measured) in most tracks, open in some, out in a few.
- **The breath before drops:** in many tracks the bar before each drop goes without the top loops and groove, or also without claps, hats, perc and bass (the kick by its own rule, fills and FX playing on).
- **Rides** (their own lane, never in intros or outros): coming in later in the first drop, all through from the second drop, or both. Each breakdown chooses on its own.
- **Drum patterns:** kick dropouts at phrase ends (e.g. the last beat or two of an 8-bar phrase), skipped kicks before a drop, clap/snare rolls, ghost notes, open-hat accents, offbeat vs 16th hats, perc swaps between sections. Applied through pattern clips (one-shots) and by gaps/edits on loop clips.
- **Fills and FX:** drum fills at phrase ends (more often before breaks and drops); a riser or snare roll whose body **ends** on the drop downbeat; downlifters and impacts that **start** on a section downbeat. **Bassy hits never on a drop:** an impact or downlifter with a lot of bass (`bassy`, `eq.ts`: 30 % or more of its power under 100 Hz in its `tone`; an impact not measured yet counts as bassy) would fight the kick, so the track's impact then opens each breakdown and build-up instead, on its downbeat, wherever no kick plays under its body (the Kick lane, or a kick roll on the Build-up lane); one without much bass hits the drops as before; into breakdowns a sweep that rises **ending** on its downbeat and/or a downlifter falling away from it. Sweeps and other FX go where their measured shape says (rising ones end on a line, falling ones start on one); unmeasured sweeps count as falling. Atmos in breakdowns. FX density varies from sparse to busy.
- **Layering:** more of the same stem where it makes sense, each layer on its own lane a little quieter: two to four **top loops** (several at once in drops, all of them in the last drop, one more per phrase in layered builds), up to three **claps** stacked on the backbeat in drops, a second hat loop and a second perc loop in drops. Never a second kick.
- **Sample picks:** one main sample per lane for the track (so it sounds like one record), variations for later drops; picks come from different zips while the library allows it (the same zip may repeat once there are fewer zips than lanes); favourites and ratings bias the picks. Loops are picked to fit the track's feel first (similar swing and push), then by the palette and how they interlock ("Picked as a record" above), then spread over zips.
- **Feel** (`feel.ts`): the groove of the track's main loop (its groove loop, else its first top, perc or hat loop with enough hits measured, §5.8b) is applied, 70–100 % of the way (a track rule), to every one-shot pattern except the kick and crash (offsets clamped to ±0.4 of a 16th; accents at half strength, at most −6 dB, relative to each pattern's loudest step so nothing gets quieter overall) and to the bass (its notes rendered on the groove). Shown as "feel of S0021's groove loop (62 % swing)".
- **Loop variations:** a top layer, the second perc or the second hat loop pitched ±1–2 semitones for the whole track (sometimes); intro loops repeating only their first bar or two in the intro's first half, the outro mirroring it (sometimes).
- **Something changes every 8 bars** (from the track's own vocabulary, "Variations of its own" above). At every 8-bar mark inside a section where nothing changes by itself (no element in or out, no fill, kick variation or crash in the bars around it), one subtle variation is added, not the same kind twice in a row: a kick variation in the bar before (not in intro/outro), the hats stopping for the last beat or two (not in intro/outro), a loop layer out for the last bar or half bar, a loop playing another part of itself for the next 8 bars (only its first bar or two, from another bar, a semitone up or down, or a short gap), a clap ghost note, a fill into the mark, a high-pass lift on a top loop. In the DJ intro and outro the kick and hats keep playing (hat loops may vary there, never stop); where only the kick plays there, a fill marks it.
- **Key:** one key per track. Tonal FX are picked from that key or its Camelot neighbours; drums ignore key. (No atmos in breakdowns any more: the ambience bed lies under the track, §6.10a; tracks made before keep their Atmos clips, but the samples have left the library, so those clips play nothing.)

**What it needs from the rest of the app**
- **Clip filter** (one of the two effects allowed in the DAW): per clip, off / low-pass / high-pass, a cutoff, an optional sweep to a second cutoff over the clip, and resonance. Same node graph in live playback and offline export (shared code, like the scheduler); editable in Arrange (clip inspector); saved in the project file.
- **Reverb builds** (the other one): a clip may send to its lane's reverb, `verb: {from, to}` (0…1), rising from `from` at the clip's start to `to` at its end, most of it late (the amount follows the square of the way through). Each lane that uses it gets one reverb: a dark hall generated in code (2.8 s decay, 20 ms pre-delay, the tail darkening from 9 to 1.8 kHz, the send high-passed at 280 Hz so kick and bass stay clean; seeded noise, so every export is the same), returning into the lane before its volume, sidechain and pan. The tail rings on past the clip, over the drop or break, and is **baked into the lane's stem** on export (no separate reverb stem). Stop cuts the tail. Same node graph and scheduler in playback and export. Splitting a clip splits its build where it is. In Arrange: the clip inspector's Reverb (Off / Build, the send at the start → at the end); the clip's label says "verb build". In Generate: the **Reverb builds** module (on/off, remembered): on the top loops, over the 2 bars into every drop and breakdown, optionally also over the last bar of every 8 or 16 bars of a section, and the amount the send peaks at (60% by default; changing it rescales the builds of generations already made). The generator splits the loops still playing there and sets the build so it peaks where they stop: before the silence before a drop or the gap before a break, so the tail rings through it.
- **Rides** (filter and fader moves, the way a producer rides them): the engine measures each part of a processed track bar by bar (`arrangements.detail`, schema v11; libraries from before are measured again by `analyze_library` from the kept originals): dB against the part's full level, and brightness, the power-weighted mean log2 frequency over 24 bands (40 Hz–16 kHz), in octaves against the part's full bars. In Generate, a bar more than 0.35 octave darker is low-passed (cutoff 16 kHz · 2^(2.2 · octaves), at least 150 Hz), one 0.35 octave thinner and at least 3 dB quieter is high-passed (60 Hz · 2^(6 · octaves), at most 2.5 kHz), with half of its level drop as a fader move; one only quieter (by 1.5 dB or more, at most 18 dB) is a fader move. Runs shorter than 2 bars are the music, not a ride. Runs become pieces that ride evenly (a sweep and/or a volume ride across the piece) while the bars between stay within half an octave and 2 dB. The bass takes the reference's bass, the top loops and groove its tops. **No low-pass on the top loops and groove while a drop plays** (it takes the drop's energy away): there a low-pass ride keeps only its fader part; builds and breakdowns ride them as measured. A section built on a real track takes the bars of it it stands for (`Section.src`, stretched or squeezed evenly); one of the grammar takes a like section (the same kind) of one of the measured tracks, the same one for the same structure (a lane made again rides the same way). Loops with a filter of their own (builds, breakdowns) keep it. Clips carry the volume ride as `gainTo` (dB at the clip's end; the gain moves evenly in dB from `gainDb`), in playback and export alike; the Arrange inspector has "ride to", and splitting a clip splits its ride. **The mix high-pass into drops** (rule `mixHp`: 1, 2 or 4 bars): every lane but FX, fills, hits, crash and disco hits high-passed from 40 Hz to 700 Hz over the bars before each drop, baked into the stems; from the reference track when most of its playing parts get 0.3 octave thinner there in most of its drops, else in about 3 in 10 tracks. Constants in `app/src/generate/rides.ts`.
- **The mix balance** (`balance.ts`): every generated lane gets a level (`Lane.levelDb`, on top of its volume slider, in playback and the exported stems) that brings it to its place against the kick, whatever its samples' own levels. Where it sits is the producers' balance in the user's tracks: the engine measures each part's K-weighted loudness (mono, LUFS) in its full bars (`arrangements.levels`, schema v13; full drum loops don't count, they're mostly kick), and Generate takes, per part, the median of its level against the kick over the tracks (at least 3, else a house default: claps −4, hats −10, tops −7, bass −2, music −8, …). Tracks whose stems were normalised one by one (80 % of at least 3 stems peaking within 1 dB of full scale) don't count. A lane's loudness is worked out from its clips where it plays in drops (else wherever it plays): the samples' energy, its pattern steps and velocities, its clip gains; rendered bass, strings and vocal parts at the render's −14 LUFS. Layers sound together: the lanes of a part (Tops 1–4 and Groove, Clap 1–3, …) keep their starting steps under each other and together sit where the part does. The kick sits at −17.5 (so a balanced mix is as loud overall as the starting mix was), levels move at most ±18 dB, and a lane with nothing measured keeps 0. A lane made again or given a new sound is levelled again. The choices say "mix balanced as in N of your tracks". The sliders still move each lane from there.
- **The mix EQ** (`eq.ts`): every generated lane but the kick, the bass and the hits (impacts and downlifters: their boom is the point) gets a low cut (a flat high-pass: hats, ride and crash at 250 Hz, perc 180, claps and tops 150, the rest 120; a build-up playing the kick keeps its lows). The drum parts (kick, claps, hats, ride, perc, tops and groove) also get a few broad bands that move their tone half of the way to how that part sounds in the user's tracks: a low shelf (250 Hz) and a high shelf (6 kHz), at most ±4 dB, then up to two bells (Q 1, 300 Hz–5 kHz, an octave apart, at most ±3 dB) where it still differs by 2 dB or more, compared from an octave above the low cut up to 14 kHz (the references' stems aren't cut as hard). FX, fills and crashes are moments, each its own sound, so an average of them is no target: they get the low cut alone. So do the stabs: the references' "music" is mostly pads and chords holding, and moving a stab's tone towards it dulled its attack. Tone is power in the engine's 24 bands against the total: `samples.tone` and `hits.tone` (schema v14, `analyze_library` for older libraries) and, per part over its full bars, `arrangements.levels.spectra` (the median over at least 3 tracks; full drum loops don't count). A part's lanes share one set of bands, from their tone together (layers keep their character against each other). A makeup gain (K-weighted, from the lane's tone, at most ±3 dB) keeps each lane about as loud as without its EQ, so the balance stands. Lanes without measured samples get the low cut alone. `Lane.eq` (bands, makeup, off): Web Audio biquads between the lane's gain and its duck, the same in playback and export, so the EQ is **baked into the stems** (no dry export). The lane panel's **EQ** switch turns a lane's EQ off and on (in Arrange an ordinary edit, ⌘Z); its tooltip, and the Arrange lane header's, say what it does. A lane made again or given a new sound gets its EQ again. The engine measures a track's stems one at a time (a track can have 40 stems of six minutes).
- **The lane compressors** (`comp.ts`, the DSP in `audio/compressor.ts`): almost every generated lane gets a compressor, set for its part and **held against the user's own tracks**; the kick (what everything else ducks to), the ride, and the moments whose shape is the point (FX, fills, crashes, hits, build-ups, atmos) get none, nor do the ambience bed and the pads (their renders' levels spread too wide, −23 to −4 dB, for one setting to fit; the bed sits 26 dB under the kick anyway). Feed-forward, both sides linked (one gain, the image stays), an RMS detector (5 ms unless set: `detectMs`), a soft knee and **no look-ahead**: Web Audio's own DynamicsCompressorNode delays its output by 256 frames (a compressed lane would sit off the grid against the rest and the sidechain) and adds a makeup gain of its own, so it is an AudioWorklet of our own (`compressor.worklet.ts`, loaded once per context), the same in playback and export, **baked into the stems**. In the chain after the lane's EQ, before its duck (compressing after the duck would flatten the pump). The threshold goes from how loud the lane's sound is where it is loudest: its samples' `punch_db` (the loudest 200 ms) at their clip gain, as most of the drops play it (renders: what their kind measures on the user's library, bass −11, strings −16.5, vocal −13.5; samples not measured: their normalised peak less 17.5 dB). It is held against the lane's sound before its volume and its mix level, so the slider doesn't change how hard it works; the release is in beats, so it breathes with the tempo.
  - **What the user's tracks said** (`tests/bench/dynamics.test.ts`: their stems where each part plays full, 8 bars each, 354 of them, against the library's sounds compressed): a part's transient (its loudest 5 ms against its loudest 200 ms) and its tail (each 16th's last three quarters against its first) are where the library's drums already sit, since their loops are cut from finished stems (claps 8.3 dB vs the tracks' 8.7, hats 7.5 / 7.4, tops 7.1 / 7.1). A slow attack moves them away: the compressor reacts after the crack and takes the body down (a clap's transient 8.8 → 11.1 with 20 ms). So the drums are caught **fast, at the hit, and lightly**; what compression can't close (the tracks' tails are fuller on perc and tops, −4 vs ±0: their sounds and rooms, not their dynamics) it doesn't chase. The ride gets none (any moved its transient under the tracks'). The bass, fast too, is evened out most. Per-lane targets from the tracks were not worth measuring per sample: the samples already match them, and the compressor hardly moves the measure.

  | Part | Threshold (against its punch) | Ratio | Attack / detector | Release | Makeup | On the user's library (mean / at the hits) |
  |---|---|---|---|---|---|---|
  | Claps | +3 dB | 4:1 | 1 / 1 ms | 0.1 beat | +3 dB | 1.8 / 4.3 dB: its tail up to where the tracks have it |
  | Hats | +1 | 2:1 | 0.2 / 0.5 ms | 0.1 beat | +2.5 | 1.2 / 3.6 |
  | Perc | +5 | 2.5:1 | 0.2 / 0.5 ms | 0.1 beat | +2 | 1.1 / 4.4 |
  | Tops, groove | +0.5 | 2:1 | 0.2 / 0.5 ms | 0.1 beat | +2.5 | 1.1 / 4.4 |
  | Bass | −0.5 | 3:1 | 0.2 / 0.5 ms | a 16th | +3.5 | 3.0 / 5.3: the notes even, the line rolls |
  | Stabs, disco hits | −2 | 2.5:1 | 25 / 5 ms | an 8th | +2.5 | 2.7 / 3.5, the attack kept (they're accents) |
  | Strings | −4 | 3:1 | 30 / 5 ms | 0.6 beat | +2 | 2.0 / 4.1, slowly: a bed |
  | Vocal | −7.5 | 3:1 | 10 / 5 ms | 0.2 beat | +4 | 2.9 / 6.1: the phrase at one level |

  Knee 6 dB (8 on strings). The makeup is what each takes off in loudness (the median over the library), so the balance stands. Measured by `tests/bench/comp.test.ts` (each part's material through its compressor; ±1 dB from one sample to the next). `Lane.comp` (threshold, ratio, knee, attack, release in beats, detector, makeup, off). The lane panel's **Comp** switch turns it off and on (in Arrange an ordinary edit, ⌘Z); its tooltip, and the Arrange lane header's, say what it does. A lane made again or given a new sound gets its compressor again.
- **The drum bus** (`busLanes`, `comp.ts`): the drums that play the groove (kick, claps, hats, ride, perc, tops and groove, layers and all: `Lane.bus`) go through one compressor heard from all of them together (`Project.drumBus`): 2:1, 10 ms attack (the kick's attack through), a 16th to recover, its threshold 3 dB under the drums' level together in the drops (each bus lane's punch at its volume and mix level, their power added), +2 dB makeup. On tracks made from the user's library that is 1.4 dB on average in the drops, 2.7 at the kicks: a gentle glue. Held against the drums of the user's own tracks summed where kick, clap and hats all play full (`tests/bench/bus.test.ts`, 35 tracks): no bus setting moves the drums much either way (the tracks' drums are a touch sharper and longer in the tail than the made ones, whatever the bus does), so it glues and stays out of the way. **The stems add up to the bus:** the bus's gain goes onto each bus lane after its own chain (`setLaneBus`: the lane's tail through a gain the bus drives), so each drum stem carries its share. Live, a detector worklet (`bus-detect`) hears the bus lanes' tails and drives their gains; in an export, the bus lanes are rendered into the detector once per range (`busGain`) and every bus stem (and the mixdown) plays that gain curve (sample-exact: checked in Electron, the stems summed against the live bus within float rounding). Its threshold is at the bus, after the lanes' volumes: turning the drums down works it less, as a bus does. The drum lanes' panel has a **Bus** switch (the whole bus, off and on; an edit of the track, ⌘Z); a lane made again keeps the bus as it was switched. *Not yet:* a pre-flight check that the lanes aren't crushed.
- **The mix, further** (`balance.ts`, `eq.ts`, `mix.ts`; all of it on every new track, in playback and the stems):
  - **Punch:** a lane of one-shots is levelled on its average loudness (as the references are measured), plus half of how much more compact its sample is than is usual for its kind in the library (`compactness` = `punch_db` against its whole energy within 200 ms; the usual: the median per category, from 4 measured samples), at most ±4 dB: a snappier hit counts louder and ends up lower, a washier one higher. Loops are levelled as before.
  - **Even levels within a lane:** a drum lane that plays more than one sample (the groove swapped in a later drop, a loop switched halfway) gets each other sample trimmed, on its clips, to the loudness of the lane's main one (the one that plays longest in the drops), at most ±6 dB, so the change of sample isn't a jump in level. FX, fills and hits are left alone (each its own sound). The choices say "1 sample levelled to its lane".
  - **Room for the main lane:** a layer (Hats 2, Perc 2, Tops 2–4, Groove) whose tone is much the same as the lane it layers (0.6 or more shared, of 1) gets a bell of −2.5 dB (Q 1) where that lane is strongest (300 Hz–8 kHz), unless the part's own tone match already put a bell there.
  - **Breakdown levels:** what stays in a breakdown (One groove) is held at one loudness under its level in the drop, `glueDb` − 4 dB, whatever its filter takes: the filter's loss is worked out from the sample's tone (a bright loop loses over 15 dB under an 800 Hz low-pass, a dark one under 3) and made up for on the clip (+6 dB at most, −12 at least), so a bright perc doesn't vanish where a dark one stays. (In the user's own tracks, hats, perc and claps that play in a breakdown play at about their full level and tone; tops about 2.5 dB down and half an octave darker. Generate's breakdowns are subtler than that by design.)
  - **Kick and bass as one measurement:** where the kick's weight is (its strongest band under 200 Hz), how long it rings, and how much of that time the bassline, as its notes sound in the track key, plays within an octave of it (its second harmonic counts half) on a four-to-the-floor kick. The sidechain's depth is the Bass module's amount + 0.5 × (collision − 0.35), within 15–95 %; it recovers over 0.8 of the kick's length (0.35–0.8 of a beat). The choices say "sidechain 78 % over 0.52 beat: the bass sits on the kick (55 Hz)". Not measured: the patch's own octave and sub (the render isn't measured before it is made), so the bass's level and low cut stay as they were.
  - **Mono low end:** the Kick, Bass, Build-up and Hits lanes are mono below 120 Hz (`Lane.monoBelow`); every other lane is low-cut at 120 Hz or higher, so the mixdown's low end is mono by construction.
  - **The drop against the user's tracks** (`checkMix`, after the balance and the EQ): every measured drum and sampled-music lane as it plays in the drops (its clips' loudness and tone, its level, EQ and makeup) is added up and compared, in five regions (under 150 Hz, to 500, to 2 k, to 6 k, above), with what the same parts add up to in the user's tracks (each part at its measured level with its measured tone; the median over the tracks, at least 3; only the parts the track has, so one without stabs isn't held against tracks with their chords in). While a region is 2.5 dB or more off, the lane that weighs most there moves 1 dB (down when there is too much, never the kick; up, the lane that lives there most, when there is too little), ±3 dB in all, and a step is kept only when the whole gets closer. The result is stored with the track (`Generation.mix`) and the choices say "mix checked against 36 of your tracks: within 1.2 dB (high mids −1.2), after Perc −1 dB". Not in it: the bass, strings and vocals (rendered, so not measured beforehand), and the dynamic range and stereo width of the finished mix (they need the render measured, and the references' full mixes).
- **Event body length:** risers and rolls must end exactly on the downbeat, but an event's `bars` includes its tail. The engine also stores `body_bars` (bars from the start to where the main sound ends); existing libraries need one reprocess.
- **Loop gaps:** dropping a loop or the kick for a beat needs no new clip model: loops get shorter or split clips, kick/clap variations are per-bar pattern clips.

**Implementation notes**
- A pure TypeScript generator in the renderer (`src/generate/`): `generate(samples, options, seed, keep) → Project`, with a seeded PRNG and the structure grammar, rule weights and pattern variations as data (easy to tune). Unit-tested without audio: constraints (DJ intro/outro, phrase alignment, FX end/start on downbeats, length range), determinism per seed, and coverage (over many seeds every variation dimension occurs).
- Generations are ordinary `Project` objects played by the existing engine; buffers are preloaded per generation, so cycling is instant after the first load. Nothing changes in export.

---

- **Listening back** (`critic.ts`, the **Listen back** option, on by default): a made track is checked from what the engine measured of its loops, and what clashes is fixed the way a producer would. It looks at the loops on the hat, perc, top, groove and ride lanes where they sound together in the drops (at least 8 bars). **Clash**: two loops' tone overlap (their 24-band `tone` as shares of power: what they share against the smaller, 0…1) × the overlap of their hits (their `groove` per 16th, as loud as each step plays, 0…1); from 0.8 the two are near enough the same loop twice and one only covers the other (in the user's library 5 % of loop pairs; half are under 0.39). The same tone on other 16ths, or the same 16ths in another tone, is layering and stays. **A kick in a loop**: 5 % or more of a loop's power under 100 Hz (the library: one top loop at 0.72, every other loop ≤ 0.02): it would flam against the track's kick. The worst is fixed first, up to 6 fixes a track: the loop at fault (a layer before a lane's main loop; never the loop the track's feel comes from, never a 🔒 kept one) is swapped for another of its kind that clears every loop it plays with, has no kick in it and fits the feel, drawn among those by favourites and ratings; when none clears them all, the one that clashes least, if that is better. The clips stay where they are (as with New sound), the lane is levelled and EQ'd again, and a swap is only taken when the track as a whole clashes less. Loops not measured yet are left alone. Seeded by the track: the same seed, library and options give the same fixes. It runs on every new track, on a lane made again (that lane's loops only) and after a choice is changed (the lanes made again only). The choices say "listened back: another loop on Tops 2 (the same hits and tone as Hats)". Not measured yet: levels (a quiet layer under a loud one), one-shot patterns, and how busy each 16th is against the reference tracks.
- **Another key** for the current generation: the key badge in Generate is a menu. The same track in the chosen key, as a new step in the history (← goes back): the bass is the same part moved into it the nearest way (the patch octave and any semitones set stay), disco hits and chord stabs are pitched for it, and tonal FX (risers, downlifters, other FX with a key) that don't fit it are swapped for ones that do: the same category, and for those leading into a line the same body length and silence before it, so they end where they did (an atmos looping under a breakdown: any length). FX with nothing else in key stay. The drums and everything else stay exactly as they are.

### 6.7 Bass: MIDI through Serum 2 (Phase 6)

Basslines are written by the app, learned from the MIDI page (learning material only: Generate never plays those files as they are); the sound comes from Serum 2 presets, rendered by the engine. (There are no keys or chord parts written from MIDI: a track's chords are the Chord Stabs page's one-shots, §6.9. Tracks made before keep their rendered Keys clips as plain audio.)
- **MIDI import** (Samples → **MIDI**, ⌘6, its own page; Process takes stem zips only and refuses a MIDI-only zip with a pointer to this page). The page is the basslines: a drop zone, the list and a "What Generate learned" panel. `import_midi(paths)`: every .mid file dropped (loose or in folders) is a bassline, whatever its name; from a MIDI zip with several parts (Bass, Organ, Strings, …) only the parts named for the bass are kept (bass/sub/808/reese), the others counted as left out (they still help find the key). The engine reads all notes (in beats, from the bar of the first note: a region exported from bar 49 of a Logic project starts on bar 1), rounds the length up to 1/2/4/8/16 bars (a last note a few ticks past a bar line doesn't add a bar) and finds the key: a key in the part's name ("Fm", "F#min", "A_maj") wins; else a MIDI zip named like a processed stem zip ("83686_midi" ↔ "83686_stems") takes that track's key; else the key all the zip's parts point to together (duration-weighted pitch classes against key profiles); a loose file uses its own notes. A zip's part is named after the zip ("83686 Bass"). Files are copied to `<Library>/MIDI/Bass/` and indexed in `midi_files` (schema v6: notes as JSON, `role` bass, `source` zip, `source_code` of the linked stem zip; rows with `role` keys, from before keys parts were removed, stay in the library unused); the same file twice is skipped. The list shows the basslines (a note thumbnail, bars, notes, source and linked track) with search, a key dropdown (`set_midi_meta`) and remove (`delete_midi`).
- **Serum 2 in the engine** (`serum.py`): Pedalboard hosts the VST3 offline, one instance for the engine's lifetime (loading takes ~10 s, rendering a few bars ~0.1 s). A `.SerumPreset` is loaded without Serum's browser: Serum's plugin state is JUCE binary XML whose `<IComponent>` holds an "XferJson" container (JSON header with an MD5 of the payload + zstd-compressed CBOR patch); a preset file is the same CBOR except that untouched sections say `"default"` and the processor's `component` entry is missing, so the engine fills those in, re-compresses, re-hashes and sets the state. Serum 1 `.fxp` presets are not supported yet.
- **Writing basslines** (`src/generate/bassline.ts`, pure and seeded). A funky house bassline is a short cell repeated: a loop of **2, 4 or 8 beats**, an 8-beat one a 4-beat cell answered by a changed ending. The MIDI library is what the generator learns from (`learnBass`); the MIDI page shows what it took from it (where notes start per 16th, the notes it plays most, how long the lines really are before they repeat, how an 8-beat loop answers, and the lines longer than 8 beats with a pointer to cut them down). Every file is read on the 16th grid relative to the root it plays on its very first 1 (the files' key labels are often wrong), one note per step, a major line with its 3rd and 6th as the minor ones (so a move to its VI is the minor VI), and **its real repeat** found, whatever its file length (a 4-bar file of a 2-beat cell is a 2-beat loop); a line that repeats only after 16 or 32 beats is learned as its 8-beat stretches (and counted on the MIDI page). Learned: the **rhythms whole**, as cells of 2 and 4 beats (each 4-beat loop gives its two halves too), with their own note lengths (as a share of the room to the next note) and velocities (as a share of the loop's loudest: ghost notes and accents stay); how the 8-beat loops' second bars answer (from which 16th, what they play there); the intervals from the root (octave included) per beat position (the 1, the 3, beats 2 and 4, 8th offbeats, 16ths) and from note to note; how many different notes a loop plays; the register (median root on the 1); how long the lines are; and the **groove check**'s ranges, from the library's own bars (10th to 90th percentile): notes per bar, the share off the beat, the share on the kicks of beats 2–4, how much of the bar sounds, the mean jump from note to note. A line favourited on the MIDI page counts 3 times. `generateBassline` writes a loop of 2, 4 or 8 beats (the length chosen, else as long as the library's lines really are). It tries 40 times and keeps the try that grooves most like the library's: each try takes one of the library's rhythms whole (a 2-beat cell, or a 4-beat one; half the time a 16th moved, added where the library starts notes, or left out, never the 1), writes new notes on it (the first the root, the rest by beat position and after each other, note-to-note tempered, until it plays as many different notes as a library loop), plays a 2-beat cell twice in the bar, and for 8 beats plays the bar twice with the second answering from its last two beats at the earliest (the learned answer's rhythm with the turnarounds' notes). The groove check scores a try by how far it falls outside the library's ranges, fewer than 2 or more than 4 different notes, jumps past an octave, an octave jump landing on a kick, and a last note far from the 1 (one leading home, the root, octave, 5th, b7 or a step under it, scores better); a library line as it is never wins. **No note is held across a kick**: every note ends by the next beat. Lengths and velocities are the rhythm's own. On a patch that glides (`SerumPreset.glide`, see Patch pool) half the lines **slide** one note into the next: a note within the same beat into a weak 16th, overlapping it by a 32nd so Serum's legato portamento glides. Notes are in the track key's scale (minor, or mixolydian major with the b7; both with the note a semitone under the root, the turnarounds' approach), the root at the octave nearest the learned register. The line has an RNG of its own (the rest of the track is the same whatever line it writes). A generated line is a bassline like an imported one (`generatedMidi`: a negative id named after its notes, "Bassline 3fa1c (4 beats)", key = the track key, transpose 0; a loop of 2 or 4 beats is 1 bar, of 8 beats 2): it renders from its notes (`render_bass` with `midi_id` < 1 needs `notes` and `bars`), and its notes go into every bass clip (`BassRender.notes`). Its timing stays on the grid: the track's feel moves it (as for imported lines). Saving a line or an edit adds it to the MIDI library, so it is learned from too. **The turn** (`turnOf`): the loop with its last beat changed, for the end of a phrase: `gap` (the beat left out, the notes before it stopping there), `octave` (the beat an octave up, down where it is high already) or `pickup` (three 16ths into the 1: down from the octave over the b7 and the 5th, or up from the 5th under the root over the b7 and the note under it; which one follows from the notes). The variation lives in the arrangement, not the loop (§6.7 In Generate).
- **Patch pool:** one Serum 2 presets folder for every module that plays Serum patches (default `/Library/Audio/Presets/Xfer Records/Serum 2 Presets/Presets`, app setting `serumPresetRoot`; older settings: `bass.presetRoot`), with a Show in Finder button. Each module picks the folders it draws its patches from on the page its parts come from (a folder includes its sub-folders): Bass on the MIDI page (a panel that folds down once it has patches). Settings → Serum 2 keeps the presets folder and a count per module. Changing the presets folder clears every module's ticks. Patches can be starred (picked more often). The engine reads from each patch whether it **glides** (`glide`: mono, legato on and a portamento time of at least `serum_glide_min_porta`): only those get basslines with a slide. App settings per module `bass`: `{folders, favorites}`.
- **Rendering** (`render_bass`): Serum back on its init patch first (a preset lists only what differs from the defaults, so nothing may carry over from the preset before), then the MIDI, transposed, through the preset, as a seamless loop at the project tempo (two cycles rendered, the second kept, so tails and modulation wrap like a repeat), loudness-matched (`bass_lufs_target`), written to `.drumvault/bass/<preset hash>-<midi id>[-g<groove hash>]-<transpose>-<bpm>.wav` (the app names the file, `bassPath`), cached until the preset or MIDI changes (renders from an older `BASS_RENDER_VERSION` are deleted once and redone). With the track's feel (`groove`: 16 step offsets in 16ths), notes that start on a 16th move by their step's offset (their ends stay). Another tempo means another render, never slicing.
- **In Generate** (a separate Bass section): each generation writes a new bassline in the track key and picks a patch. **New bassline** writes another one for the current generation; **Any / 2 / 4 / 8 beats** sets the length of new basslines (remembered; a length saved in bars before reads 1 bar as 4 beats, longer as 8) and writes one at once. The section shows the line's length in beats and whether the patch glides. A transpose of a written line (an octave up) carries over to the next one. (A line from the MIDI library, kept from an older session or saved, still plays transposed into the key the nearest way, a major part in a minor track via the relative key.) The bassline repeats through every drop, strict, and **turns** at phrase ends (rule `bassTurn`, an RNG of its own: at the end of each drop 3, every 16 bars 3, every 8 bars 2, never 2; tracks made before: never): the last loop before each of those lines (and before the drop's end, keeping the drop's own gap there) is a clip of its own playing the turn (rule `bassTurnKind`: a 16th run into the 1 3, the last beat out 2, an octave up 2), `BassRender.turn` on the line's notes (a line with its notes at hand: written or edited; the file names it, `-t<kind>`), so an edit of the line, another patch or another key carries over to its turns; breakdowns get it high-passed (its sub out, 150–450 Hz, as the 22 measured tracks do; never low-passed) or not at all, builds out / high-passed / a high-pass letting the sub back in towards the drop, intro and outro usually without (sometimes high-passed in their inner half), all as the track's rules. The section browses in place: previous / next / random patch (with ★), a new bassline, transpose by semitone or octave, sidechain depth, and bass on/off for new generations. The octave buttons (−12 / +12) are remembered for the patch (app settings `bass.octaves`: semitones by preset path, within ±24): every next track with that patch plays its part in that octave, on top of the move into the track key, and switching to another patch swaps the old patch's octave for the new one's. The patch's saved octave shows next to the buttons. Semitone steps are for the current track only. Keep toggles hold the bassline and the patch. "Rendering with Serum 2…" shows while a part renders (the first one loads Serum).
- **Sidechain:** a lane with `duck` (0…1) dips by that much on every kick hit (pattern clips with a kick one-shot, also kick lanes not being exported), reaching full depth in 4 ms and recovering over 0.6 beat; scheduled by the shared scheduler (`kickHits`) for live playback and export alike. The Bass lane gets it from Generate; in Arrange a lane with a sidechain shows an extra slider in its header.
- **In Arrange** a bass clip is an audio clip with `bass: {preset, presetName, midiId, midiName, transpose}`; it moves, repeats, trims, splits, filters and fades like a loop. The right-click menu adds transpose ±1 semitone / octave, next / previous / random patch and **New bassline** (one written line for all selected bass clips, in the key they play now: the root on its first note, minor unless it plays a major 3rd and no minor one); they re-render and play on. A written line has no "back to the imported MIDI": it is its notes.
- **Piano roll** (one loop of 1–16 bars): double-click a bass clip in Arrange (or "Edit notes…" in its menu), or **Edit notes** in Generate's Bass section. Click to add a note (a 16th, or the selected note's length; drag right away to size it), drag to move in time and pitch (16ths, ⌥ 64ths), drag a note's end to resize, right-click / double-click / ⌫ to delete, ↑↓ ←→ to nudge the selected note (⇧↑↓ an octave); a velocity lane below; loop length 1/2/4/8/16 bars. The roll shows the pitches as heard (with the transpose). Each edit (on mouse-up) re-renders the loop through Serum; the edited notes live in the project (`BassRender.notes` / `bars`, at the MIDI's own pitch) and apply to every clip of that bassline in the track (Generate: the current generation, and kept generations when the bassline is kept); the render file is named after the notes. **Revert** goes back to the imported file; **Save as new bassline** writes the loop as a .mid to `MIDI/Bass/` and indexes it (engine `save_midi`; saving the same loop twice gives the existing one), and the track switches to it.
- **Export:** `midi/Bass.mid` (named as its lane) holds the bass part as notes (looped, trimmed and transposed as in the arrangement, the turns as they play, a slide's overlap kept), to play through the real Serum patch in Logic; it has its own WAV stem.

### 6.7a Bass Samples (Phase 6)
A bass is a Serum 2 patch or a one-shot bass sample. Either way the bassline is the one Generate writes (§6.7): only what plays it differs.

- **The page** (Music → **Bass Samples**, also in the View menu): the Disco Hits page for bass one-shots, one note per file. The same import (trimmed, peak-normalised, copied to `<Library>/Bass Samples/`, `hits` rows with `kind = 'bass'`, a file already on any page skipped). Its **note**: from the file name ("Deep Bass A", "808_F#": stored as that note's major key, only the root is used), else from its pitch (the median of its fundamental over its first second, 27–260 Hz, pYIN). A sample without a note isn't used; the key menu and the pitch fix correct one read wrong.
- **Playing a line** (`basssample.py`, through `render_bass`: a `preset` under `Bass Samples/` is a sample, not a Serum preset file): like a sampler. The sample is taken to sound its own note on the note of that name nearest the middle of the line, so most notes move it little; every note is the sample played faster or slower to its pitch. One voice: a note plays as long as it is held and fades out over 30 ms, or is cut over 5 ms where the next one starts; velocity scales it from 40 % to full. The loop wraps (a note ringing past the end comes round to the start). The result is loudness-matched and written like a Serum render (`.drumvault/bass/…`, the same naming and cache), so the track's feel, the piano roll, the octave buttons, the key menu, the sidechain, the mix balance and the MIDI export all work as for a patch. Thresholds in `config.py` (`bass_sample_*`).
- **In Generate** (the Bass module's **Source**: Serum · Samples · Both, remembered; Both by default): with both kinds available a new track gets one kind or the other with even chances, however many there are of each (decided by the seed alone, so the drums are the same either way), then one of that kind, starred ones more often. The patch row steps through and randomises over the chosen source; a sample shows as "Sample" with "Bass Samples" as its folder. New sound on the Bass lane, and Arrange's next/previous/random patch, draw from the same pool.

### 6.7b Pads: the breakdown layer (Phase 6)
A layer made for breakdowns, so they have something new instead of only the drop darkened: a pad holding the key's chord, or a reese holding its root, through a Serum 2 patch.

- **Patches:** the **Pads** module's own folders under the Serum 2 presets folder (picked on the MIDI page under **Pads patches**, saved as `pads.folders` in the app settings; shown in Settings → Serum 2). A patch with "reese" (or "bass", "sub") in its name, folder or tags is a **reese**: one note, the key's root between E1 and D#2 (monotone, no harmony), mono below 120 Hz and without the low cut. Any other is a **pad**: the key's chord around middle C (root, third, fifth, the root an octave up). Without a key: none.
- **What it plays** (`character.ts: padNotes`): the chord or note held over a 4-bar loop, rendered through the patch like the bass (`render_bass`, under `.drumvault/pads/`; `BassRender.role = 'pad'`), so it is cached, follows the tempo and is moved into another key with the rest (the key menu writes its notes again).
- **Where:** in every breakdown of a track that has one (rule `padIn`: by the character, 5–9 in 10 tracks when there are patches), from the bar the breakdown has stripped down to (**the breakdown's shape**, `breakShape`: a breakdown of 32 bars strips for 8 bars, of 16 for 4, a shorter one not), to its end. It swells in over 2 bars, low-passed from `padHz` (250–600 Hz; a reese an octave lower) and opening to 7 kHz (a reese 1.8 kHz) as it rises 8 dB into the next part; into an outro it holds, half that far down. The silence and the breath before a drop take it out with the rest.
- **In Generate** (the **Pads** module: on/off, remembered): the track's patch and what it holds, **New break layer** (another patch; in a track without one, **Add a break layer**). The choice Breakdowns → **Break layer** (a pad or a reese / none). On the **Pad** lane, levelled 11 dB under the kick by default, its stem `Pad.wav`.

### 6.8 Disco Hits (Phase 6)
One-shot stabs, brass hits, orchestra hits and the like that Generate drops at key moments, moved into the track key.

- **Import** (Samples → **Disco Hits**, ⌘7, its own page): drop audio files (.wav, .aif, .aiff, .flac), folders or zips. Each file is one hit: trimmed from its attack to where its tail stays below peak −60 dB for 50 ms (at most 6 s, a 10 ms fade at the end), resampled to the library rate, peak-normalised to −1 dBFS and written to `<Library>/Disco Hits/`. Indexed in `hits` (schema v10: name, path, original path, SHA-1, key, `key_source`, `pitch_fix`, length); the same file twice is skipped. Thresholds in `config.py` (`hit_*`).
- **Key:** from the file name when it says so ("Brass Stab Cm", "Hit_F#_maj"); a bare note between separators ("Disco_Hit_F_02") is the root, major unless the sound says minor on that root; else from the sound (the engine's key detection; marked "key from the sound" so it can be checked). The page lists the hits with play, the key (a dropdown to correct it, then "set by you") and remove (`import_hits`, `set_hit_meta`, `delete_hits`).
- **In Generate** (the **Disco Hits** module, on/off, remembered): about 6 in 10 tracks get disco hits, one or two of them (taking turns), by the track's rule: on the 1 where each drop starts and halfway through it; every 16 or every 8 bars of the drops; or where every drop and breakdown starts, and halfway through drops. They are 1-bar pattern clips on their own lanes (Disco Hit, Disco Hit 2), placed after everything else, so the rest of the track is the same with or without them. Their own RNG; the lane's rules re-roll with it. **New disco hits** (Add disco hits when the track has none) draws the hits and their rule again for the current track, always with some hits and others than it had where the page has more; everything else stays exactly as it is, and it is a new step in the history (← goes back).
- **Pitch:** a hit is moved from its key into the track key the nearest way (to the relative key across major and minor: a C major hit sits in A minor as it is), plus its `pitch_fix`, within ±12 semitones; played faster or slower like a sampler (clip pitch). The module lists the track's hits with play (at that pitch) and a pitch slider (−12…+12; double-click: the move into the key alone). Moving it changes the track at once and saves the difference as the hit's `pitch_fix`, so later tracks pitch it the same way. A hit without a key only gets its fix.

### 6.9 Chord Stabs (Phase 6)
Organ, piano, synth and string chord stabs that every generated track plays, in the track key, in a funky rhythm: one-shot samples from the Chord Stabs page. (There are no keys parts written from MIDI and no Serum stab patches: tracks made before keep theirs as plain audio clips.)

- **Import** (Samples → **Chord Stabs**, its own page, also in the View menu): the Disco Hits page for stabs. The same trimming, key reading and corrections; the files go to `<Library>/Chord Stabs/` and the rows to the same `hits` table with `kind = 'stab'` (schema v12; older rows are `'disco'`). `import_hits` takes `kind`. A file already on either page is skipped. In Generate they are one-shots of category `chord_stab`. Each hit also stores `punch_db` (as samples, §5.9) and `voices` (schema v16): how many notes it plays, the pitch classes holding 0.35 or more of the strongest one's power over its first 0.6 s (`key.count_voices`; a single note shows one or two, its fifth ringing in its harmonics; a chord three or more). Hits from before are measured by `analyze_library`.
- **One to three stabs per track** (on the Stab, Stab 2 and Stab 3 lanes), different samples drawn from the Chord Stabs page's (others than the track had, where there are), in every track while the page has some and the **Chords** module is on. Each is moved into the track key like a disco hit (the relative key across major and minor, plus its `pitch_fix`, within ±12). The choice is the track rule `stabs`; the bass is written the same way either way.
- **One loop** (rule `stabLoop`, every new track with stabs that fit; `src/generate/stabs.ts`): the track's stabs are one 1- or 2-bar riff, the same all through the track, changing only by leaving things out (the lean version, the turn every 8 bars, the phrase of rest). How many (rule `stabCount`: one 3, two 5, three 2) and what each does (rule `stabLayout`, `loopJobs` / `loopParts`): a second stab is **layered** on the first (`stack` 3: both on every hit, the layer 4 dB under it: one bigger stab) or plays its **pickups** (`split` 2: the hits on the 16ths between the 8ths, in a bar that has a hit on an 8th; the first stab the rest); a third plays the pickups under a layered pair. Without pickups in the rhythm a second stab is layered and there is no third. The main stab sits in the middle, its layer 0.15 right, the pickups 0.25 left. Choices: Sound → Stab loop (off: taking turns, as tracks made before), Stab sounds, Second stab.
  - **Every hit full** (velocity 3): they are the track's accents. The lean version keeps each bar's anchor (its first hit on an 8th).
  - **Which stabs**: the fit below, times how tight a hit each is (`focusWeight`): the share of its energy in its loudest 200 ms (from `punch_db` and `energy_db`, no new measurement), full from 0.5, down to 0.15 for a sustained or swelling sound (a pad-like stab sounds soft at any level). The listening back draws its swaps the same way.
  - **Rhythm:** with no saved rhythms, a classic 55 % of the time (the one that sits best against the bassline), else drawn around an **anchor** (an off-beat 8th both bars hit: the "and" of 1 or 3 most, of 2 or 4 less) with the funky 16ths around it, bar 2 repeating bar 1 half the time (where the bass does too). With saved ones, 60 % take one as it is. The bassline only leans the rhythm (in its rests: 0.5 where a note starts, 0.85 where one sounds, 1.25 in a rest; on its syncopations 1.8 against 0.8).
  - **A moved hit** (rule `stabMove`, 40 % of loops; the house organ's lift): the last hit of the loop (its second bar; `stabMoveAt` `loop` 3) or of every bar (`bar` 2) a tone up (4), a fourth up (2), a minor third up (1.5) or a tone down (1.5), on all the stabs playing it. A loop (or, for every bar, a bar) of one hit has nothing to answer and doesn't move. `PatternClip.bend`: semitones per step on top of the clip's pitch, played like a sampler (live and in export). The step sequencer rings the moved step. Choices: Sound → Stab moves, Stab move on.
  - **Drops hit open and whole:** no filter opening over drop 1 or every drop (`stabsOpen` none) and no lean first drop (`stabsGrow` off) are drawn for a loop (both stay choices; dub's opening is left out); the drop's first bar is dry and open.
  - **They announce every drop** (rules `stabAnnounce`: 4 bars 2, 8 bars 3; `stabRoll`): over the last bars of a build (at most its length), of a breakdown (at most half of it, in place of its opening) and of an intro of 24 bars or more going straight into a drop with the tease on (in its place; an intro into a build keeps the tease). Bar by bar: a low-pass from 0.6 of the track's cutoff (350 Hz at least) opening to 7 kHz, its resonance rising from 0.8 to 7 dB (Web Audio's Q), the room from 0.18 to 0.4, the delay from 0.12 to 0.5, 4 dB down at first rising to 0. The last bar: a **roll** (none 2; in 8ths 2; 8ths then 16ths 1: the main stab and its layer, gated so the hits don't ring into each other), **dry from its last beat**, thrown 0.9 to the delay, so the echoes ring into the silence before the drop and the drop comes in dry. A loop in a build plays it dark (at the announcement's start, 4 dB down) until the announcement, unless the build rule keeps the stabs out. Choices: Builds → Stabs announce drops, Stab roll into drops.
  - They duck 10 % under the kick (not 25).
- **Taking turns** (tracks made before the loop, or with Sound → Stab loop off): how many (rule `stabCount`: one 4, two 4, three 2; never more than the page has, nor than the rhythm has hits over 2 bars) and how they share the one rhythm (rule `stabTurns`, `stabParts` in `src/generate/stabs.ts`): two stabs a bar each, call and response (the rhythm over 2 bars, when both bars have hits), or hit by hit, going round from the first hit over 2 bars (always so with three). No two stabs ever hit on the same step; a stab's tail rings on under the next one's hit, as from a sampler without choke. Both are choices under Sound (Stab sounds, Stabs take turns).
- **Rhythm:** one rhythm per track, 1 or 2 bars of 16 steps, each on or off. Built in (until rhythms are saved): half the time a classic house stab rhythm (the "and" of 1 and 3, the 16th after an offbeat, …), else 2 bars drawn from the funky 16ths (the offbeat 8ths most, then the 16ths just after them, rarely with the kick), mostly 2 stabs a bar, sometimes 1 or 3, at least an 8th apart, the second bar the same or answering the first. The part merges into 1- or 2-bar pattern clips.
- **Step sequencer** (in the Chord Stabs module): the track's rhythm as 16 steps a bar, 1 or 2 bars; a click turns a step on or off and changes the track at once (the same stab where it played, the rest as it is, in place in the history). **Save rhythm** (named; app settings `stabs.rhythms`) keeps it for Generate; saved ones are listed (click: play it in this track; ×: delete). Once there are saved rhythms they replace the built-in ones: about 1 in 3 tracks takes one as it is, the rest one learned from them (as many bars as they tend to have, as many stabs a bar, on the 16ths they hit per bar with a little room for others, bar 2 repeating bar 1 as often, no closer together than they get).
- **Placement** (per track, rule `stabsIn`): in the drops only, or also (`'keys'`, where keys parts used to play) in breakdowns the same rhythm low-passed or nothing at all (never sparser or different), in builds low-passed, a low-pass opening up or nothing. Never in the DJ intro and outro. They play on through the breath before drops; the silence before drops and the mix high-pass apply to them. Stabs don't take the track's feel: they sit on the grid.
- **In Generate** (the **Chords** module): on/off for new tracks (remembered), the track's stabs (numbered when there are several; the step sequencer marks each step with the stab that plays it) with play and the pitch slider (as for disco hits, saved on the stab), where they play, and **New chord stabs** (another stab, rhythm and placement; on a track without stabs, made while the module was off, it adds them). The rest of the track stays exactly as it is; a new step in the history. A stab lane's re-roll button makes the track's stabs again; its New sound gives that lane another sample in the same turns. The key menu moves them with the rest. An RNG of their own: the drums and the bass are the same with or without stabs.
- **Stabs that fit** (rule `stabFit`, on for every new track; the choice Sound → Stabs puts a track back to "placed as before": any stab, the rhythm drawn on its own, straight on the grid, starting and stopping on the lines. Tracks made before are remade that way):
  - **Which stabs** (`stabWeight`): drawn by how well they fit. Near the key: a stab moved up to 2 semitones counts 1, 3 → 0.6, up to 5 → 0.25, further 0.08 (a sampler changes a sound with its pitch). Not the top loops' tone over again: its weight falls by up to 0.6 with how much of its tone is theirs. As a set: a second and third stab of the first one's kind (chords with chords, single notes with single notes: the engine's `voices`, a chord from 3) count 1.6 times, one whose tone is the first's (0.9 shared) 0.2 times, and more the further apart their registers (full weight from 0.8 octave).
  - **The rhythm** is written for the track (`stabRhythm` with a fit; a saved rhythm taken as it is stays as it is): against the bassline's own notes, by the track's rule `stabBass`, in its rests (7 in 10: a step where a bass note starts counts 0.08, where one sounds 0.6, a rest 1.7) or on its off-the-beat note starts (3 against 0.5); bar 2 repeats bar 1 only where the bass does the same in both. How many stabs a bar follows the stabs: single notes are a riff (2–4), long (0.8 s) or chordal ones accents (mostly 1–2). The stabs take on the track's feel like the other one-shots.
  - **Phrasing:** the first stab of each bar full, the ones answering it softer (velocity 2; not in a loop). The last bar of every 8 turns, by the track's rule `stabTurn`: its last stab left out, a 16th early, or said twice. Under a sung vocal phrase no stab plays at full strength.
  - **Through the track:** a slow filter opening from `stabsCutoff` to open over the first bars of drop 1 or of every drop (`stabsOpen`; half the drop, 8–32 bars); a first drop on the lean rhythm (the first stab of each bar) until halfway (`stabsGrow`); never a phrase of rest inside a drop (once `stabsRest`: tracks made with it play through when remade); a dark, soft tease of the lean rhythm over the last 8 bars of an intro of 24 bars or more (`stabsTease`: 16 bars stay clean for the DJ). In breakdowns they stay as the drums do when the rules keep them (also breaks & builds, low-passed): closing over the first 4 bars, held 3 dB down and no louder than velocity 2, opening over the last `glueOpen` bars, out for the bare middle of the long breakdown; otherwise they leave over two bars past the line, darker and softer, instead of stopping on it.
  - **Effects:** a stab that would ring into the next one is **gated** (`PatternClip.gate`: 0.92 of the gap to the next stab of the rhythm, a quarter beat at least; it fades out over its last 30 %, 60 ms at most). The stab lanes send 18 % to a **short room** (`Lane.room`: the lane's reverb as a room of 0.55 s instead of the builds' hall), so stabs from different packs sit in one space, and **duck** 25 % under the kick over 0.4 beat. **Delay throws** (`stabEcho`: the last bar of every 8 or 16 bars of a drop, or only the bar into a breakdown): the bar's stabs sent 50 % to the lane's delay (`Clip.echo`), which repeats them a dotted 8th later and again, 0.42 of each repeat coming round, losing lows (350 Hz) and highs (3.8 kHz) each time; in the lane's stem like the reverb. Two stabs sit 0.25 left and right; of three, the first in the middle.
  - **The moments too** (every track): disco hits, fills, impacts and downlifters on the Hits lane, crashes and FX are levelled the same way, hit for hit, instead of on their average over the bar (which turned a lone disco hit or a short fill far up). **How hard each hits is the user's tracks'**: the arrangement measures each hit part's loudest hit (`levels.hits`: the K-weighted level of its loudest 200 ms, as a sample's `punch_db`: kick, clap, crash, fills, fx (risers, sweeps), impact (impacts, downlifters), stab (music stems named as stabs or chord hits); older arrangements are measured again by `analyze_library`, one without its zip only marked), and each part's step is the median of its hit against the clap's over the tracks that have both (at least 3; `hitSteps`). Where they don't say, the steps measured on the user's 45 tracks: crashes **+1** (they were set 6 dB under: 4.5 dB quieter than in the tracks), fills **+6.5** (a roll is loudest as it lands; they were set 1 under: 7.3 dB quieter), FX **+1** (the second and third layers 2 and 3 dB under it), impacts and downlifters −0.5, disco hits −1 (no tracks to say). Measured against the tracks the same way (`tests/bench/levels.test.ts`: each lane rendered whole as it plays, its loudest 200 ms against the kick's), crashes, fills and stabs now sit within 1 dB of them. Every moment's hits stay at least 1 dB under the kick's (loudness against loudness). On the Fills, Hits, FX and FX 2 lanes, which play several samples, each clip is trimmed (±9 dB) to the loudness of the lane's main sample, so one hot fill isn't louder than the others.
  - **Level, hit for hit** (`balance.ts`, every track): a stab lane isn't levelled on its average loudness (the references' "music" is pads and chords playing all the time: a sparse, short stab was turned up until each hit was far too loud, a median 5.5 dB over the kick and up to 11.5 in the user's library) but on one hit's loudness (its `punch_db`, the loudest 200 ms; before that is measured, its energy over its length): a touch harder than the clap's hits (+0.5: the user's tracks' stabs hit 0.6 dB over their claps; 6 dB under the kick's without a clap; they were once 3 dB under, and with the softer answering hits most stabs sat 7 dB under the clap: too soft for the track's accents), and their hits at least 3 dB under the kick's: loudness against loudness (it was the kick's own gain less 1 dB, which held a quiet stab sample 3–7 dB under the clap in about a quarter of the tracks; a track led by its stabs has them 1.5 dB up, under the same ceiling). The mix check never moves a stab lane; when it moves the clap, the stabs and the moments (disco hits, fills, impacts, crashes, FX) are levelled again against the clap as it is then (a fill was left up to 4 dB under the clap it plays with). **Fills** are capped by loudness, not gain: each fill's hits at least 1 dB under the kick's hits (a fill sample is often far quieter than a kick sample, so the gain cap held quiet fills down before drops).
  - **Listening back** (`critic.ts`): a stab moved 4 semitones or more, or 0.85 of whose tone is the tops', is swapped for one of the page's that is neither, drawn by the same fit; its rhythm and where it plays stay. Not a 🔒 kept stab.
  - The choices say "one stab loop: in the bassline's rests, …, the loop's last hit +2 st, announcing drops over 8 bars (filter and delay rising, a roll in eighths, thrown into the drop)" (tracks made before: "stabs written for the track: in the bassline's rests, a turn every 8 bars (the last stab early), a filter opening over drop 1, delay throws every 16 bars, gated, moved −2 st into the key". Choices: Sound → Stabs; Drops → Stab filter, Stabs in drop 1, Stabs in long drops; Every 8 and 16 bars → Stabs every 8 bars, Stab delay throws; Intro & outro → Stabs. Constants: `STAB_*` in `generator.ts`, the weights in `stabs.ts`.

### 6.10 Strings (Phase 6)
Long string samples under the track, heard as they were recorded: no warping, no wash, no chopping. Some tracks have them: in the drops, all through, or all but the intro and outro. Strings are made from samples only (no Serum). (They replace the drones of earlier versions: tracks made before keep their Drone clips as plain audio, played from the files they have; the Drones page's samples stay in the library unused.)

- **Source:** the **Strings page**'s samples (Samples → Strings, also in the View menu: the Disco Hits page for strings, `hits` rows with `kind = 'strings'` in `<Library>/Strings/`; up to `strings_max_len_s`, 60 s, kept of each file, where a hit keeps 6; the key from the name or the sound, as for hits). A sample needs a key to be used.
- **In the key, its length kept:** a sample is moved into the track key the nearest way (the relative key across major and minor, plus its `pitch_fix`) with Rubber Band, so it plays as long as it was recorded. Only samples within 3 semitones of the key (`STRINGS_MAX_SHIFT`, `src/generate/strings.ts`) are used in a track; when none is that close, the track has no strings.
- **Every 8 bars:** the sample starts again on every 8-bar line of the part (the clip loops an 8-bar render). **Rendering** (`strings.py`, through the bass pipeline: `render_bass` with `out_rel` under `.drumvault/strings/`, cached by sample, transpose and tempo): the sample from its start, pitched, cut to 8 bars at the track tempo with a fade over `strings_fade_s` (0.25 s) where the next start cuts it, or padded with silence when it's shorter; loudness-matched at −14 LUFS like the bass, held at −1 dBFS peak. Thresholds in `config.py` (`strings_*`).
- **A supporting layer** (every track with strings): **As long as the sample:** a part runs as many bars (8, 4, 2 or 1) as the sample fills by at least 90 % at the track tempo (`stringsBars`), and the sample starts again on that line: a 4-bar sample every 4 bars, never 4 bars of sound and 4 of silence (a part shorter than 8 bars is its own render file, `…-b4-…`; a sample that ends a moment before its part does fades over 20 ms, `strings_tail_fade_s`). **Where** (rule `stringsAt`): from the second drop on (the second half of a track's only drop), in the second half of every drop, or in the breakdowns for tension (without breakdowns: the second half of drops); never under the intro or the outro. Tracks made before keep "in every drop", "all through" or "all but intro and outro" (still in the choice's menu). **In at once, out with a fade:** a part is there from its first beat (it starts where a part of the track does: on a drop, a breakdown, the line halfway through a drop, after the fill or the crash) and leaves over 2 bars (a quarter of a short part at most); only strings from the very start of a track (an older "all through") swell in. In a breakdown it rises 6 dB from its start to the drop and stops with it over half a bar. **Level:** 18 dB under the kick (it was 13), on top of the lane's sidechain: under the track, not on it.
- **In Generate** (the **Strings** module, on/off, remembered with the sidechain depth): about 2 in 3 tracks get strings (rule `stringsIn`) when a Strings page sample is close enough to the key, placed by `stringsAt` (in the drops 3, all through 2, all but the intro and outro 3). One Strings lane, its clips running through breakdowns; the silence before drops and the mix high-pass apply to it (strings running through a drop play on after the silence from where their part is). The lane ducks under the kick (60 % by default, the module's slider; in Arrange the lane's). Its mix level sits at the house default (−13 dB against the kick) with a 150 Hz low cut. The module shows the sample, where it plays and how far it's moved, **New strings** / **Add strings** (another sample and place; a new step in the history), and the sidechain. The Strings lane's **New sound** takes another sample, keeping where it plays; **Remake** draws that again. Its choice (where) is under Sound. The key menu moves them into the new key: the same sample when it's still within 3 semitones, else another that is, else they go. An RNG of their own: the rest of the track is the same with or without strings. Keep holds them.
- **Export:** a stem like any lane (`stems/Strings.wav`); no MIDI (it's a sample, not a melody).

### 6.10a Ambience: the bed under a track (Phase 6)
A long texture very quietly under a generated track, the air that keeps it from sounding dry.

- **The page** (Music → **Ambience**, also in the View menu): the Strings page for textures, up to a minute each, copied to `<Library>/Ambience/` (`hits` rows with `kind = 'ambience'`). A texture is one of two:
  - **Noise** (vinyl crackle, tape hiss, room tone, a crowd, rain, a field recording): **no key**, **never pitched**, in any track.
  - **A tonal bed** (a drone, a soft pad, an atmosphere holding a note or chord): **always pitched** into the track key (Rubber Band, its length kept), the nearest way to the key or its relative (plus its `pitch_fix`), within a tritone. It is **never heard as recorded**: a track it wouldn't move in (its own key or the relative one, the shift coming to 0) doesn't get it, nor does a track without a key.
  - **Which:** measured on import (`ambience.tonality`, `hits.tonal`, schema v18): the share of its energy between 200 Hz and 5 kHz (where the bed is heard, over its low cut) in narrow peaks 10 dB over the spectrum around them that **hold for a second**: a held tone does, crackle, rain and a crowd flicker. From 0.06 (`ambience_tonal_min`) it is tonal (measured: noise 0.00–0.03, tonal atmos 0.11–0.7, a pad under loud noise 0.5); a name calling it noise (crowd, applause, cheering, chatter, crackle, hiss, static, noise, rain, wind, waves, water, room tone, street, traffic, birds, forest; not when it's also called a pad or a drone) is noise whatever it measures (a crowd singing along still is a crowd). A tonal bed's key: from its name (an atmos cut: the stem's), a bare note in it with the sound's scale, else the sound's. Thresholds in `config.py` (`ambience_tonal_*`). Textures from before are measured by `analyze_library` (`measure_textures`).
  - **The page shows** which it is ("tonal bed: always pitched into the track key" / "noise: never pitched") and a key menu: a key set by hand makes it a tonal bed in that key, **No key: noise** makes it noise.
  - **The Splice page suggests** both (4 s or more): noise by a name with vinyl, crackle, hiss, tape, room tone, ambience, atmos, texture, noise, field, rain, crowd, static, foley or air, no word of music, drums, FX, a riser or a fall, and no key in the name ("loop" is fine when it's named as noise: a crackle loop); a tonal bed by a name with drone, pad, soundscape, ambient, bed, or a texture word with a key, and no word of chords, a melody, an instrument of another page, drums, a riser or a fall, sidechained or pumping, an arp, vinyl, tape or resampled (a record sampled is music).
- **Atmosphere goes here, not to the drum library** (`hits.add_texture`): an atmos stem's cuts (8-bar chunks, as before) are written to the Ambience page when a zip or pack is processed, with no key (the user's choice: a texture is never moved, the atmos stem's key notwithstanding), measured like an imported texture; a cut already there by its bytes isn't added again. The processing summary says "N textures to Ambience". Libraries from before: `analyze_library` (run by the app at start while any atmos is in the library) first moves every atmos sample there (`atmos_to_ambience`) and **deletes it from the library for good** (row, file, peaks), and deletes atmos waiting in the library's trash for good too. The Library has no Atmos category among its FX any more.
- **The loop** (`ambience.py`, through `render_bass` under `.drumvault/ambience/`, its `transpose` the tonal bed's shift, 0 for noise): the texture (a tonal bed moved into the key first) made into a seamless loop of 16, 8 or 4 bars at the track tempo (the most it fills; a shorter one laid end to end): its end crossfaded (equal power, 1.5 s, `ambience_xfade_s`) into its start, so it repeats with no seam. Loudness-matched at −14 LUFS.
- **In a track** (rule `bedIn`, 85 % of tracks when the **Ambience** module is on and the page has textures; an RNG of its own, so the rest of the track is the same with or without it): one clip on the **Ambience** lane from the end of the intro to the start of the outro (the DJ mix-in and mix-out stay clean), a 1-bar fade at each end, **constant**: no rides, no filter, through the silence and the breath before drops and outside the mix high-pass. **Very quiet**: 26 dB under the kick by default (the lane's slider moves it), low-cut at 200 Hz, **ducking** 50 % under every kick. The **key menu** moves a tonal bed into the new key, or another one that moves takes its place, else the bed goes; noise stays. The module: on/off (remembered), the track's texture (and how far a tonal bed is pitched), **New ambience** (another texture; **Add ambience** in a track without). Stem `Ambience.wav`.

### 6.11 Vocals (Phase 6)
A track can sing a short vocal, made for it in Create: AI-generated with ElevenLabs, lyrics written for this app, as House of Tracks allows (original lyrics, no celebrity voices, each vocal used once, edited: phrased here), or a Splice vocal loop (§6.11a). **One vocal per track**: a made vocal replaces a loop, a loop replaces a made vocal (the same Vocal lane). Generate never makes an ElevenLabs take on its own (there's no library of made takes to pick from); it may give a new track a Splice loop.

- **ElevenLabs:** the API key in Settings → ElevenLabs, kept encrypted with the macOS keychain (Electron safeStorage, `<app data>/elevenlabs.key`), never in settings.json; the section shows the plan and credits left (`GET /v1/user/subscription`). A restricted key needs Music (access) and User (read). Requests ElevenLabs answers busy (429, 503) are tried again after 5, 15, 30 and 60 s.
- **Making a vocal** (Create, the **Vocals** module of a generated track's side panel, or a vocal lane's ⋯): **New vocal** (**Add a vocal** in a track without one) makes a take with everything drawn: what it sings (a chant of one short line 3, a pair of short lines 2, a longer sung phrase 3, two phrases 2: a long line answered by a short one, or two long ones; from the app's lyric bank, `vocals/lyrics.ts`: club chants of 2–6 words and phrases of 7–12, no verses or choruses), a female voice 3 in 4, a mood (gospel 35, soulful 35, airy, deep and uplifting 8 each, dark 6), sung in the track's key (any key, minor twice as often, for a track without one) and a length in bars at the library tempo plus a second (chants 8 or 12 bars, sometimes 16; phrases 12 or 16): credits go by the second (≈ 900 a minute, the split half again). A fold-out (**Choose the lines and voice**) takes typed lines, a voice, a mood and a length instead (**Make this vocal**). Each take: `POST /v1/music` (music_v1, a composition plan: one hook section, its lines repeated, styles for a nearly a cappella, dry, repetitive house vocal at the tempo in the key; no drums, verse, chorus), then `POST /v1/music/stem-separation` (`two_stems_v1`), into `<Library>/Vocals/<date-time>/` (take.mp3, stems.zip → stems/, vocal.wav at the library rate, meta.json with the lines, voice, mood, key, response headers and song id), then analysed. Starter plans get 128 kbps MP3 (192 from Creator, WAV from Pro). It takes a minute or two; work goes on meanwhile, and a take finished after its track was closed is not placed anywhere. The take is placed as below, an edit of the project (⌘Z goes back). Each take belongs to the track it was made for: one replaced by a new vocal is never offered again, and nothing lists the takes. The module shows the take (its lines, voice, mood, the key heard) and how it's sung, and the credits left.
- **Analysis** (`vocal.py`, after each take): ElevenLabs keeps the tempo but a cappella takes have no beat, so it is read from the repetition: the lags where the take's pitch (pYIN) and level line up with themselves about as well as anywhere (a line sung again, both lines again) are its **phrase loops**, each cut from the onset of its first line after a rest and stretched to whole bars at the library tempo (1, 2, 4 or 8; at most 20 %), faded at their ends, at −14 LUFS. **No chops** (they're out, the user's call: none are cut; `analysis.chops` stays, always empty). The **key** is read from the notes sung (pitch classes weighted by level, against major and minor key profiles). Thresholds in `config.py` (`vocal_*`).
- **Placing it** (the generator's vocal rules, an RNG of their own, `rerollVocal` with the one take): its phrase loop only (no chops); the long or the short loop (`vocalLoop`); the phrase in the drops 3, in their second halves 2, in drops and breakdowns 3 (a reverb build on it in breakdowns), or in breakdowns and the last drop's second half 1 (`vocalAt`). Never in the DJ intro and outro. Lanes **Vocal** (the phrase: a render through the bass pipeline, `role: 'vocal'`, `.drumvault/vocals/`: the loop moved from its sung key into the track key the nearest way by Rubber Band with formants kept, `--formant`, and stretched to the track tempo) (tracks from before keep their **Vocal Chops** lane: one-shots on the nearest root, third or fifth of the key, moved with the key menu; making the vocal again sings the phrase only). Level at the house default (vocal −3 against the kick, or the user's tracks', below), low cut at 150 Hz. **Remake** on the vocal lanes sings the same take another way (no credits); they have no **New sound** and no Keep. The key menu moves it into the new key. Its choices are under Sound. In Generate the Vocals pill isn't shown; a shortlisted track from before that sings one shows its vocal lanes as they are.
- **Export:** stem `Vocal.wav` (and `Vocal Chops.wav` in a track from before); the instrumental masters next to the others; the takes marked used.
- **Where and how loud, from the user's tracks:** their vocal stems (filed as "ignore", never a sample source) are measured with the arrangement (`arrangement.py`), apart from the parts so sections, rides and the balance stay as they were: `arrangements.levels.vocal` (its bars "0"/"1"/"2" and the loudness of its full bars), `levels.vocals_measured` (looked for; older arrangements are measured again by `analyze_library`, one without its zip only marked). A track built on one of them (a template) sings where it does: in its breakdowns (`breaks`, or `drops_breaks` with its drops), its drops' second halves only (`halves`) or its drops (`drops`) (`template.ts: vocalRuleOf`, applied after the template's redraws). Without a template the `vocalAt` weights are how often the user's tracks sing where (`vocalAtWeights`), else the house weights. The Vocal lane's level is the median of the vocal against the kick over those tracks (at least 3, not normalised), else the default −3.

### 6.11a Vocal Loops: Splice vocals (Phase 6)
Vocal loops and phrases from Splice, sung by some new tracks the way a made vocal is.

- **The page** (Sounds → **Vocal Loops**, also in the View menu): drop files or folders, **Add vocal loops…**, or add them from the Splice page. Each is made into a take (`vocalloop.py`, RPC `import_vocal_loops`) in `<Library>/Vocals/splice-<sha1>/` like a made one (vocal.wav, phrases/, analysis.json, meta.json with `source: 'splice'` and `splice`: its file, where it was, its bytes' SHA-1, pack, label, link, tempo, loop or not, where its key came from, Splice's tags): placed, rendered and marked used exactly as an ElevenLabs take. One without a phrase loop isn't sung. A file already there (by its bytes) is skipped. 1.5 s to 4 minutes (`vocal_loop_min_s`, `vocal_loop_max_s`).
  - **Splice's record** of it: the desktop app's own database (`~/Library/Application Support/com.splice.Splice/users/*/*/sounds.db`, read only; `Settings.splice_db` to point elsewhere), by its path, else its name: pack, label, pack permalink, tempo, key (root and major/minor), loop or one-shot.
  - **A loop** (it has a tempo: Splice's, else the name's): its phrase loop is its whole bars (1, 2, 4 or 8; of a longer one, a pack's whole hook, the 8 bars on a 4-bar line it sings most in) stretched to the library tempo. **A phrase** (no tempo): on the fewest bars that hold it at the library tempo (at most 8), not stretched, silence after it. Its **key**: the name's, else Splice's (a root without major/minor takes the scale sung on it), else the one sung.
  - **Its link**: the pack's page, `https://splice.com/sounds/packs/<label>/<pack>/samples`. Splice keeps the pack's part but not the label's, so the label's is tried from its name (as it is, then -records, -samples, -audio, -sounds, -music, -recordings: "Toolroom" → toolroom-records) against splice.com (a 200, 6 s at most each) and remembered per label (`<Library>/.drumvault/splice_labels.json`). None answering: no link; the page sets one by hand (only splice.com links). The link opens in the browser (`shell:openSplice`, splice.com only).
  - Each row: ▶ (its phrase), its key, tempo, phrase bars, pack and label, the link (**edit** / **set link**), **Used in …** with **Offer again** (an export thrown away: it goes back to the pool), ✕.
- **In new tracks** (G; the **Vocal Loops** module: on/off, remembered): a track sings a loop 60 % of the time (`LOOP_CHANCE`, an RNG of its own: the rest of the track is the same with or without) when one fits: **never exported**, sung within **2 semitones** of the track key the nearest way (the relative key counts as the key; `LOOP_MAX_SHIFT`) and within **4 BPM** of the track tempo (a phrase without one: any; `LOOP_MAX_BPM`). It's moved into the key with its formants kept and placed as a made vocal is: where and as loud as the user's tracks sing (§6.11).
- **The module** (Create): the loop the track sings with its pack's link, **New vocal loop** / **Add a vocal loop** (another that fits, replacing what the track sings), how many unused loops fit the track.
- **Exported:** the loop is used (`usedIn`) and never offered to a new track again; the export's `info.txt` names its file, pack, label and link (§6.5).

### 6.12 Splice (Phase 6)
A page (Music → **Splice**, also in the View menu) that looks through the Splice folder on the computer and shows the sounds that could go on the Chord Stabs, Disco Hits, Strings, Bass Samples, Ambience or Vocal Loops page. It only suggests: nothing is added until the user adds it.

- **The folder:** `~/Splice` unless another is chosen (**Folder…**, saved as `spliceFolder` in the app settings). It is only read. The page scans when it opens and on **Rescan**.
- **The scan** (`splice.py`, RPC `scan_splice {folder}`, answered directly; about a second for 1,500 files): every audio file's name and header, nothing else. Its **length** from the header; a **tempo** in the name (a number from 70 to 180 on its own, unless the name says one-shot); the **key** in the name ("Dmin" → Dm), or only its root for a bare note ("…_F": the import reads the scale from the sound); its **pack** (the folder under `packs`). Whether it is on a page already is told by its bytes (the import's own SHA-1 check).
- **What is suggested, by the words in the name:** brass, horns, sax, disco or orchestra, short and not a loop → **Disco Hits**. Strings (string, violin, viola, cello): short and a hit or one-shot → **Chord Stabs** ("a short string stab"); 3 s to a minute → **Strings**, with "a string loop: check it holds at other tempos" when the name has a tempo (the Strings page plays a sample as it was recorded). A chord, stab, piano, organ, keys, Rhodes or clav that is short and not a loop → **Chord Stabs**; a synth one-shot or hit only when its name gives a whole key (a bare note is a single note). Short is up to `hit_max_len_s` (6 s), or `splice_stab_max_len_s` (12 s) for what its name calls a one-shot, a stab or a chord (the import trims it). A bass, sub, 808 or reese that isn't a loop (no "loop", no tempo unless it is called a one-shot), up to 6 s → **Bass Samples** ("a bass one-shot"). A vocal loop or phrase → **Vocal Loops** (§6.11a; a word of vocal, vox, voice or acapella, and none of an FX, a noise, an instrument, drums, a mix or a texture; a loop within 8 BPM of the library tempo, `vocal_loop_suggest_bpm`, its tempo the number in the name nearest the library's; a one-shot only when called a phrase, hook or chant; 1.5 s to 4 minutes): "a vocal loop at 124 BPM" or "a vocal phrase"; adding it is the Vocal Loops page's import (it can't go on another page). A texture → **Ambience**: noise ("noise for the ambience bed: never pitched") or a tonal bed ("a tonal bed: pitched into each track's key"), by the words in §6.10a. Left out: anything named a drum, a bass loop, a vocal FX, FX (unless it is called a stab or a chord), a lead; loops of anything but strings (and of crackle and the like, for the Ambience); sounds under 0.15 s. Thresholds in `config.py` (`splice_*`), the word lists in `splice.py`.
- **The page:** each suggestion with ▶ (played from the Splice folder; the app reads only files inside it), its pack, length, key, tempo and why it is suggested; **Add to <page>** for the page suggested, and a menu for another page. Adding is that page's own import (§6.8–6.10): the file is copied into the library, trimmed, its key read. One that is in the library shows "In Chord Stabs". Filters: all or one page, hide what's added, search by name, pack or key.

## 7. Phases & acceptance criteria

### Phase 1 — Engine + CLI (no UI)
- All of §5 implemented and runnable through the CLI.
- `tests/make_fixtures.py` generates synthetic zips with a programmatic kick at known BPMs (e.g. 122, 124, 126; source tracks are always whole-number BPM), hats, claps, a top loop, a bassline + chords in a known key, a "silent breakdown" section, mixed naming conventions, `__MACOSX` junk, and one stem with a meaningless name.
- **Acceptance**
  - BPM is detected within ±0.02 of the truth on all fixtures; grid phase is correct.
  - The key is correct on all fixtures.
  - Loop starts are sample-exact on the grid after stretching (verify with a test that checks kick onsets fall on the bar start ±1 ms).
  - Silent breakdown sections produce no loops; repeated identical bars dedupe to 1 loop.
  - Each one-shot category yields ≥1 clean hit with an intact transient (no fade-in, peak within the first 10 ms).
  - Running on 3 of Lars's real zips produces a library he judges usable by ear. **This is the real gate before continuing.**

### Phase 2 — App shell, Process & Library views
- Electron app with sidecar management (spawn, restart on crash, health check), the settings screen, a first-run library folder picker, and dependency checks.
- Process view complete (§6.2), including overrides + reprocess.
- Library view complete (§6.3), including auditioning and filters.
- **Acceptance:** drop 20 zips at once; the queue works through them while the user browses the library; overrides/reprocess work; the library list stays smooth with 5,000+ samples.

### Phase 3 — Arrange: timeline + playback
- Lanes, audio clips, pattern clips with the step editor, markers, editing operations, undo/redo, zoom, save/load/autosave, and the transport.
- **Acceptance:** build a 192-bar arrangement with 8 lanes; playback is in time with no drift or glitches; save → reopen gives an identical project.

### Phase 4 — Export + polish
- Stem export (§6.5), the clipping check, the MIDI markers file, "find similar", favorites/ratings, "rebuild loops at new BPM", keyboard shortcut overview, and an unsigned local `.app` build (electron-builder; the Python engine bundled with PyInstaller onedir, or pointing to the uv environment). *Chosen: the uv route.* The `.app` carries the engine source and `uv.lock`; on first launch it runs `uv run --frozen` into `~/Library/Application Support/Drumvault/engine-venv` (needs `uv` and `rubberband` from Homebrew). Ad-hoc signed so it launches on Apple Silicon.
- **Acceptance:** exported stems imported into Logic at bar 1 at the same BPM line up sample-accurately with each other and with Logic's grid.

### Phase 5 — Generate view
- The Generate view in §6.6: the structure grammar and variation dimensions, fast cycling with history, keep toggles and seeds, the overview and section jumps, and Send to Arrange. Plus what it needs elsewhere: the per-clip filter (playback, export, Arrange inspector, project file), `body_bars` for events (engine, schema, reprocess), and short gaps in loop clips.
- **Acceptance:** with ≥ 5 processed zips, a new generation is ready and playing in under a second (after the first buffer load); every generation is 4–6 minutes with a DJ intro and outro of ≥ 16 bars on kick + hats, phrase-aligned sections, and risers/rolls ending exactly on drop downbeats; samples come from ≥ 3 different zips and tonal FX match the track key; over 100 seeds the structures differ and every variation dimension (kick treatments, build styles, pattern variations) occurs; the same seed gives the same generation; Send to Arrange opens an editable project that plays and exports like any other.

### Phase 6 — Bass (MIDI + Serum 2)
- §6.7: MIDI import, the Serum 2 host and preset loading, bass rendering, the patch pool in Settings, the Bass section in Generate, sidechain ducking, bass clips in Arrange, and the bass MIDI in the export.
- **Acceptance:** dropping a folder of bass MIDI imports every file with bars, key and role (duplicates skipped); with preset folders chosen, every generation has a Bass lane playing a newly written bassline (learned from the MIDI library) through a Serum 2 patch in the track key in every drop (high-passed or out elsewhere, by the track's rules); next/random patch or a new bassline is heard within a second once Serum is loaded; the bass ducks under the kick by the chosen amount in playback and export; Send to Arrange keeps the bass editable (transpose, patch, bassline); the export writes the bass as `stems/Bass.wav` and `midi/Bass.mid`.

## 8. Development notes

- **Prerequisites (macOS):** Node 20+, `brew install rubberband uv`, Python 3.12 via uv.
- **Prerequisites (Linux cloud sessions, Phase 1 only):** `apt-get install -y rubberband-cli libsndfile1 ffmpeg`, `pip install uv`. Distro Rubber Band may be 2.x without the R3 engine (`--fine`); detect this and fall back to the default engine there. Full setup steps live in `CLAUDE.md`.
- **Dev run:** `cd engine && uv sync` → `cd app && npm install && npm run dev`. In dev, the app spawns the engine with `uv run python -m drumvault_engine`.
- Never block the Electron main process; all heavy work happens in the sidecar. Audio decode happens in the renderer.
- Keep engine types and TS types in sync: define the RPC/DB shapes once (in `engine/drumvault_engine/schemas.py` with pydantic) and mirror them in `app/src/types/` (manual sync is fine, or generate the TS from JSON Schema).
- Every analysis threshold lives in `config.py`, never hard-coded inline, so it can be tuned against real material.
- Log every processed zip's analysis summary to `<Library>/.drumvault/logs/` for debugging bad results.
